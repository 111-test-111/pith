# AGENTS.md — pi-app

Pith is an Electron coding-agent client: Pi SDK (`@earendil-works/pi-coding-agent`, 1.0.0) in main, React/beUI in renderer. Read [README.md](README.md) for setup and [docs/README.md](docs/README.md) for implementation details. Keep this file focused on development rules.

## Build and verification

```bash
npm run dev          # electron-vite with HMR
npm run typecheck    # main/preload and renderer
npm run build        # production output in out/
npm run preview      # run the built app
```

Always run `npm run typecheck && npm run build` after changes, then affected suites through `npm test -- --no-prepare --suite <id>`. `npm test` prepares and runs standard suites; `npm run test:list` lists the source-owned catalog. Checks use fixtures/Electron/CDP and Node assertions. Missing adapters are SKIP, not coverage. See [testing](docs/testing.md) for layers, reports and CI. For an unbuilt delivery, verify before removing output.

Keep electron-vite/Vite/React-plugin peer compatibility. Main/preload/workers remain ESM `.mjs`, with `out/main/index.mjs` as the explicit entry. Use `npm run preview` for the correct userData directory; if Electron installation was skipped, run `node node_modules/electron/install.js`. Preparation scripts patch the pinned SDK, restore the macOS PTY helper mode and generate file icons; review patches on SDK upgrades.

## Ownership and process boundaries

| Area | Owner |
| --- | --- |
| IPC data | `src/shared/types.ts` and dedicated `src/shared/` protocols |
| SDK sessions, events, snapshots, admission | `src/main/pi/manager.ts` |
| App settings | `src/main/settings.ts` (`AppSettings` is the single source of truth) |
| IPC handlers / bridge | `src/main/ipc.ts` / `src/preload/index.ts` |
| Renderer state | `src/renderer/src/state/pi-store.ts` |
| App compositions / Settings registry | `src/renderer/src/components/app/` / `settings/SettingsPage.tsx` |
| Vendored beUI | `components/motion/`, `components/agents/`, `components/charts/` and their helpers |
| Theme, geometry, transcript rhythm | `src/renderer/src/styles.css` and the corresponding `lib/` token modules |

Paths below use renderer/main-relative shorthand where clear.

- Renderer uses only typed `window.pi`, never Electron/Pi imports. New IPC needs shared DTOs, main handlers and preload methods. Main owns Node/process work and sends data; renderer composes UI prose.
- `AppSettings` lives at `<userData>/app-settings.json`; do not duplicate its shape. Active cwd drives sessions, file indexing and commands; known folders are presentation state. Projectless chats use `main/pi/default-workspace.ts`'s stable internal workspace, never listed as a project or exposed as a project path.
- Startup uses the saved active session and configured preference, with deterministic folder fallback; never select the boot session from incidental file mtimes.
- Publish restored sessions before extension startup finishes; `lifecyclePromise` gates prompts/catalog/reload, and `initializing`/`session_initialized` release send without losing drafts. Every session owns its mutable loader/runtime; dispose with `session_shutdown` before invalidation.
- Quit is bounded and idempotent (`main/shutdown.ts`); stop admission before cleanup, stop the scheduler before sessions, and never let repeated Quit bypass cleanup or task wakes restart work.

## UI rules

### beUI, icons and localization

- All UI primitives are beUI; no other UI kit or hand-rolled controls. App glue in `components/app/` composes beUI with `styles.css` theme tokens.
- Prefer app wrappers over vendored edits. Required minimal patches carry `// local patch (pi-app):`; preserve them on registry updates. Add with `node scripts/beui-add.mjs <slug>` (`--check` is read-only; existing files are never overwritten), installing listed deps separately. Never ship/import registry previews.
- UI glyphs use only `lib/icons.tsx` (`GLYPHS`, `IconComponent`/`IconProps`): square interfaces use Remix Icon Line, squircle interfaces use Hugeicons Stroke Rounded (native 24-grid at 1.5 stroke). Remix selections prioritize centered, compact, nearly square silhouettes, with the closest readable semantic match. Both families retain their native 24-grid artwork consistently across sizes. Preserve Remix's filled outlines without adding strokes, stretching paths or overriding viewBoxes. Ship its Remix Icon License v1.0 in `src/renderer/public/licenses/remix-icons.txt`. Shortcut keycaps alone use the vendored Lucide SVGs in `src/renderer/public/lucide-keycaps/`, through the same adapter without a Lucide dependency; keep their licenses and regenerate `lib/keycap-artwork.ts` with `node scripts/generate-keycap-artwork.mjs` after artwork updates. Ordinary arrows follow the active family. `lib/app-artwork.tsx` holds the app-owned gap drawings for both families; the Phosphor pin/pin-off vendored there keep their upstream 256 canvas as filled shapes rather than being rescaled, with their license in `src/renderer/public/licenses/phosphor-icons.txt`. `lib/icon-metrics.ts` owns 16/18/20px UI canvases; shortcut marks fit the interface font's capital height and retain Lucide's native stroke. Registry imports route through this adapter; animated marks follow it too, revealing Remix's filled artwork without stroke-drawing it.
- Branding stays app-owned: `resources/pith*.svg`, `lib/brand-icons.ts` and `ProviderIcon.tsx` masks. Animated marks use pack data; settled statuses use adapter `CircleCheck`/`CircleX`/`Ban`. Only the shared r=9 waiting arc is app-drawn, with reduced-motion support. No private settled circles. `@phosphor-icons/react` remains rollback only, without source imports.
- File artwork uses app-owned square Pierre adaptations in square and native Codex Pierre Icons with a local Sass override in squircle through `FileTypeIcon.tsx`/`lib/file-icons.ts`, at 16px trees/tabs and 18px cards. Original SVGs/notices live in `resources/bearded-icons/` (GPL-3.0) and `resources/pierre-icons/` (Apache-2.0); app document/media additions and overrides live separately in `resources/pierre-icons-extensions/` with `lib/pierre-file-icons.extensions.json`. Preparation generates ignored `src/renderer/public/file-icons/`, including licenses and addition notices. Relative URLs support packaged `file://`; preserve native Pierre paths/opacity in the upstream snapshot and share its theme palette. Square SVGs live in `resources/pierre-icons-square/`, with angular interiors and adaptation notices; the explicit native exceptions retain their complete original SVGs. Keep custom sources outside upstream refreshes. Bearded assets/maps remain available for rollback. Commit lookup maps and upstream snapshots; keep additions outside the refreshable snapshot, and folders/toolbars stay UI glyphs. See [file icons](docs/file-icons.md) for exceptions and refresh commands.
- All app-owned renderer prose, errors, placeholders, aria-labels and tooltips use `useI18n().t()`. Add flat keys to `i18n/locales/en.ts` and to every Chinese dictionary (`zh-CN.ts`, `zh-TW.ts`), with `{name}` interpolation. Add a locale to `Locale`/`LOCALE_NAMES`/`dictionaries` in `i18n/index.tsx` plus `localeFromLanguageTag`, and cover it in any check that pins a locale. `zh-TW` is Taiwan Traditional Chinese: convert from `zh-CN` (OpenCC `s2twp`) and then apply Taiwan terminology (軟體/網路/檔案/資料/設定/使用者/伺服器/快取/載入/匯出/匯入/搜尋/驗證/逾時/中斷點/擴充功能/資料夾), never the raw character conversion alone. Use native `LOCALE_NAMES`; pass labels into beUI rather than translating its internals. Spinner sentence tables intentionally live in `lib/spinner-verbs.ts` (`en`/`zh`/`tw`).
- Allowed rendering engines are not substitute UI kits: `react-markdown`, Temml, xterm, pdf.js, native media elements and browser webviews. Their surrounding controls remain beUI.

### Geometry, motion, scrolling and forms

- `styles.css` owns corner tokens: default square is zero; the later squircle preset supplies the scale. Use semantic radii, never literal pixels/numeric props. Native `corner-shape` handles portals too; no circular clip/SVG masks or per-frame paths.
- `rounded-full` is truly round for status/loader geometry; `rounded-capsule` follows UI style for avatars/chips/badges/selection marks, while single-icon buttons take `rounded-icon`. Selection frames use `rounded-control corner-round`, with distinct radio/checkbox marks. Boolean settings use `Checkbox mark="square"`, never Switch. Images use `rounded-item` thumbnails / `rounded-window` previews (28px squircle, covering native window corners).
- Tab fills/indicators use shared `fillRadius` in `tabs.tsx`: pill triggers take control, compact segment/underline take inner. Compact tabs retain symmetric padding/no negative margin and the centre line shared with adjacent controls.
- Floating surfaces alone use `shadow-overlay`; no content hover lift or generic Tailwind drop shadows. Nested diffs keep one frame. Controls never scale on press/hover. Respect `lib/reduce-motion.ts` and CSS signals without spoofing OS preference.
- Nested confirmations keep parents mounted, suspend parent trapping, focus Cancel and restore focus with `preventScroll`. Share `useModalScrollLock`; portal children outside clipped/transformed parents. Popover exit releases pointer/focus immediately.
- Hide scrollbar chrome globally only. Pad focusable scrollports; use shared `useScrollFade`/`FadeScroll` 12px ramps only at obscured edges, with caps on line boundaries.
- Wheel scrolling preserves both axes and accepts direction changes immediately; file scrollers use `use-wheel-scroll.ts` and shared unit/Shift normalization in `lib/wheel-gesture.ts`. Preserve pinch/zoom shortcuts and overscroll boundaries; image pans and pointer dragging remain two-dimensional. See [wheel gestures](docs/wheel-gestures.md).
- Record editors use `lib/form-standard.ts`: two-column grid (wide fields span), `data-form-items`, 20px item gaps, 14px controls, foreground medium titles flush with controls, 10px title/control gap. Use `FORM_PANEL_TITLE`, `FORM_INPUT_LABEL`, `FORM_FIELD_TITLE`/`FORM_FIELD_HEADING`; stacks are `flex flex-col gap-1.5`. Hints/errors are 11–12px, 6px below. Pickers take `textClassName="text-sm"`; composer keeps its scale. Cap for short windows only; normal windows show all fields.
- Settings sections extend `SECTIONS`, preserving the shell and lazy-first-mount/keep-mounted content. Context menus use one trigger/target resolver per surface, not one per row; reuse existing action props and typed IPC.

### Workspace, composer and transcript

- `main/window-chrome.ts`/`WindowTitlebar.tsx` own one title row; composer owns model selection. Later actions use `TitlebarOverflow`. Compact/reload share palette handlers; live compaction waits for a complete response/tool boundary, while reload refuses live turns. Title-row control glyphs draw the compact 16px canvas (`size-4`), the same canvas the sessions sidebar uses; text-adjacent marks (breadcrumb, labelled buttons) keep their text size.
- `lib/panel-layout.ts` separates preferred and fitted widths. Resize writes each panel's own CSS variable and commits state on release, preserving sibling floors/`CHAT_MIN`; no ancestor hot-path writes. Keep transcript `content-visibility: auto`, with the two live-edge rows always laid out: a fresh row mounts below the fold, so `auto` had no remembered size for it and painted the 400px fallback for a frame instead of the row's real height. One right-rail mode owner preserves docked preference/active pane and makes covered chat inert in fullscreen.
- Pane layouts use `sidebar-pane-layout.css`'s named container, not window/fullscreen conditions. Never remount/re-fetch because width changed; source/diff, terminal, browser, table and media canvases stay full width. See [pane layout](docs/sidebar-pane-layout.md).
- Composer uses native `contenteditable="plaintext-only"`/`use-prompt-editor.ts`: no React subtree rebuild on input, preserving IME/selection/undo. Mentions/annotations commit one editing transaction. Plan controls stay outside the editor/scrollport in the bottom row; no textarea overlay/text-indent.
- Composer/edit attachments share `lib/attachments.ts` (preload paths, workspace fallback, pathless clipboard images). Rail changes span ChatView `railItems`, MessageItems `data-rail-id` and MessageScroller.
- Render `PiStore.messages` with `streaming` as overlay; mirror the full SDK role union. Preserve creation-time order (`insertByTimestamp`) for late retries. Live turns stay open; settled turns fold process before the final reply block. Completion stamps give elapsed time; each tool retains its own execution-end time.
- `styles.css`/`lib/transcript-rhythm.ts` own rows, indents and gaps. Use transcript hooks, not extra flex gaps/negative margins. `tool-runs.ts` owns grouping/row counts; `tool-categories.ts`/`tool-icons.tsx` own category/glyph mappings. Two bundled extensions deliberately draw ONE glyph for the whole family rather than one per tool — context-mode (`ctx_*` → `Columns3Cog`) and pi-lens (→ `Codesandbox`) — and the folded `context` group wears the same glyph as its rows.
- `turn-written-files.ts` derives committed successful edits/writes and persisted child writes; pending/failed intent never renders. Read `details.patch`, not `details.diff`; synthesize successful writes. ChangeScopes owns files independently of folds and hides active scopes until settlement. Share ReviewDiff/FileDiff, bounded previews and windowed bodies.
- Images share `ImagePreviewProvider`; only successful read-image/browser screenshots use bare image output. Failure retains text/frame. Overlay viewport stays transparent; only caption/control bars paint fills. Markdown keeps shared plugins, source normalization ahead of the parser (quoted math, space-bearing link destinations), parser-produced math, lazy Temml/fonts, per-block error boundaries, streaming fences/escapes and native inline baselines. No raw HTML/DOM math scanning or empty `mathTextData` tokens.

## Session, tool and execution invariants

- SDK events flow through JSON-serializable `pi:event` → `PiStore.dispatch`. Coalesce hot `message_update`/`tool_execution_update` deltas; flush ordered events first. Status/metadata (`context_usage`, browser, subagents, sandbox, ask-user, scheduler) must not acquire transcript `eventSequence`; Plan/Jev own independent revisions.
- Only `agent_settled` (or `pi_error`) ends a run; `agent_end` precedes retries, compaction and queued continuations. `prompt()` resolving alone is not completion. Preserve SDK callbacks whole, including auth and compaction payloads.
- Branch state derives from the complete selected `getBranch()`, never compacted message arrays. Todo updates only after committed successful `todo_write`; compaction does not erase tasks, empty lists retain the preceding list and cancelled differs from completed. Sidebar/index/search must honour selected-branch facts and child/scheduled markers.
- SDK queues expose text only. `queueMirror` retains images, original text and file paths; pending payloads are a list, duplicate delivery removes the first occurrence and queue rebuilding publishes one final state. Base64 images never ride events. Stop pauses wake owners and recalls queued messages before abort, because SDK abort does not clear queues. Overlays get Escape before Esc-to-stop.
- `main/bash/manager.ts` owns background processes independently of SDK calls. Wait expiry returns the same task; timeout kills the tree. Preserve bounded durable logs/cursors, check notification `canStart` before launch and never recover ownership from persisted PIDs.
- Completion notifications wait for the persisted originating toolResult, steer with `triggerTurn` and acknowledge consumption; bash never uses follow-up. Stop/rewind/resend/delete/quit pause/cancel owners; switching/reload do not kill commands. Todo/background/subagent/Q&A/Jev share one full-bleed task-strip overlay, never pushing the transcript.
- Ask-user supports blocking/async receipts and settles on teardown. Skip is cancellation; only first real interaction cancels its deadline. Async questions outlive call abort; only actual answers wake idle turns. Validate owner/request IDs, surface child asks under the parent and project records from the full branch.
- Subagents are real managed sessions, not a lightweight parallel loop. Dispatch freezes profile ∩ parent active tool ceilings and restrictions; resume may narrow, never widen. Children have independent Todo/ChangeScopes/notification owners, no RewindRecorder, conditional extension loading and explicit `debug: true` grants. Opening a child is read-only; actions pin `expectedRunId`. A run completes only after its child background work drains and result persists. Persist run-scoped child-write evidence on the parent so outcomes/deleted child files cannot erase Rewind coverage. Read [subagents](docs/subagents-implementation.md) before changing runtime/profile policy.
- Scheduled tasks (`main/pi/scheduled-tasks/`, `shared/scheduled-tasks.ts`) use durable locked atomic storage, revisions, timezone/DST rules, single catch-up and no replay of accepted prompts. Existing-session runs enter ordinary idle/Plan/work/wake admission, never steer into user turns. New scheduled sessions freeze config, stay hidden/read-only, omit ask/escalation/Jev and open in read-only rail panes. Drain work before outcome; retain cancellation ownership through cleanup.
- Session list/search are indexes, not UI-triggered rescans. Worker search verifies normalized literal matches and groups full cwd before pagination. Bound/fingerprint caches and bump `INDEX_VERSION` with semantics/schema. Sidebar ordering/pins never edit SDK files or change membership through dragging.
- Totals use SDK stats over all entries; live context uses context usage/post-compaction estimate. Include standalone/summary/tool billing without double-counting nested calls or inventing attribution. Context detail carries statistics only.

## Safety, Plan, Rewind and recording

- DSH confines first-party bash/edit/write file effects using branch-stored session mode; app settings only choose new-chat defaults. Canonicalize roots/ancestors, check each side effect and never fall back to host bash without a confined runner. Escalation is one-shot; Plan/children/scheduled runs cannot escalate. File policy implies no network/plugin isolation.
- Plan is a selected-branch fact layered over permissions. Use its synchronous transition lock and work reservations on every asynchronous admission. Full read-only tool definitions are identity-checked; held execute references recheck admission and child ceilings. Plan shell requires full DSH without host fallback. Mode/latest submission fold the full branch.
- `submit_plan` alone creates bounded canonical Markdown. Main stamps identity/hash; await persistence, fsync/seal before publishing. Preserve `finishTurn`, queue guards and continue adapter. Approval fsyncs requested → mode → exact user-entry-linked started; keep opening private, cancel on Stop, never replay recovery. Export uses reference/Save As. Live branch maps execution; durable started approval hides from transcript/rail. See [Plan Mode](docs/plan-mode-implementation.md).
- Rewind checkpoints bind only before user turns (`message_start` barrier, `message_end` entry). CheckoutCoordinator leases fence tools/processes/terminals/children; recovery fences extensions. Restore uses reviewed immutable plans, SHA-256 CAS, quarantine/backups/journal, never Git checkout/reset. Persist branch selection before commitment; single-file restore preserves staging/conversation. Undo/Redo target latest checkout.
- Coverage is explicit successful edit/write and child-write evidence from the full selected branch. Missing/excluded originals need consent listing every skipped path; never touch skipped paths/ancestors/index entries, infer shell writes from prose or rebuild originals from output. Persist skip reasons through history/Undo/Redo. Read [Rewind](docs/rewind-implementation.md) before touching transaction or coverage paths.
- Image validation precedes tool-image persistence; invalid bytes become bounded notes, valid images stay byte-for-byte. Historical and text-only transformations apply to request copies only. Budgets also modify only request copies: preserve users, tool-call/result pairs, images, state-bearing output and current batch; only older large tool text shrinks after estimating schema/system overhead. Wrapper order is Plan → text-only image guard → budget → trajectory → provider, dispose in reverse. Diagnostic budget metadata is not provider usage/payload. See [budgets](docs/context-budget-implementation.md).
- Recording retains serializable public Tool fields without handlers; retries share a logical run and every attempt settles. Continue retains frontier/ChangeScope with no user row/checkpoint or executable incomplete calls. Resend branches/re-prompts, updating sequence when SDK emits none. Fork uses a separate SessionManager because branching mutates its receiver. See [replay](docs/session-replay-implementation.md)/[trajectory](docs/present-trajectory-implementation.md).

## SDK, extensions, MCP, Jev and debug

- Trust installed `.d.ts`, not stale web examples; Pi AI/core packages are nested under the coding-agent package. Images are `{type: 'image', data, mimeType}`; assistant messages have no ID, so existing role/timestamp correlation remains necessary. Thinking levels come from `getAvailableThinkingLevels()`, never a fixed list.
- Ordinary sessions omit SDK `tools` allowlists (they also hide extension tools); children keep their frozen allowlist. Activate direct/model-only tools for model declaration while codemode/deferred MCP tools remain registry-callable. Service-controlled tools register at build and toggle active membership live, reapplied after reload.
- Catalog uses the live loader/package manager, dedupes tool names and invalidates on registration/exposure changes; retain disabled-extension snapshots. Families follow declared categories/owners, never first name segments. Package/toggle/skill actions return fresh catalog; surgical skill edits accept only loader-known paths.
- Nested `ctx.executeTool()` rechecks Plan/child ceilings, holds Rewind leases and records writes even if outer calls fail. Receipt-bearing stateful tools are model-only. Codemode uses explicit schemas and `{ok,isError,data,content,error?}`; fulfilled failures still require `isError`. Use typed cursors, not notice parsing. Native MCP owns tools/resources; filter the legacy adapter. See [MCP/codemode](docs/native-mcp-codemode.md).
- Context-file inclusion is read live through `agentsFilesOverride` during reload. Global/project append prompts are trusted files cached per session; edits reload idle sessions and defer live ones to settlement. No catalog-only second loader or mid-run reload.
- Jev stays main-owned through the official SDK. Workflow is inactive in Plan and never recursively wraps children. Preserve hidden branch guidance, redacted out-of-context traces, independent revisions and cancellation/admission. Continuation needs a concrete target/new evidence; stalled/repeated reviews remain unresolved. Routes do not narrow tools. Keys stay in 0600 `jev-auth.json`; connection tests are synthetic. See [Jev](docs/jev-integration.md).
- Debug actions pin chat/`debugId` and stopped references pin `stopId`. Register starts before awaits; hold process leases through cleanup. `debug/action-registry.ts` owns policy/schema. Core inspection is read-only; positive source refs use typed `debug:source`, addresses remain strings. Clear instruction breakpoints on restart, retain source intent and separate virtual-source versions. Child grants freeze explicitly and completion closes its debugger. See [debug](docs/debug-implementation.md).

## Files, browser and terminal

- File panes are read-only, absolute-path rail tabs over typed bounded readers. `FileBrowserStore` owns lifetimes/view/scroll outside mounts, bounded caches dedupe reads and reject superseded responses. Source/search/highlighting run in disposable workers with windowed rows and packaged grammar support. Save As copies full original bytes, never capped previews.
- `shared/preview.ts` is the one routing table; `readsAsText` is the only document-read gate and `shared/extension.ts` the extension splitter. Media streams through the Range-capable custom scheme, never whole/base64 text; PDFs use exclusive-end range IPC and ordered lazy pdf.js imports; tables parse bounded records/ZIP ranges in workers; fonts use bounded IPC. Keep preview engines isolated/read-only and layouts windowed. HTML uses a confined read-only loopback origin and memory-only guest with no preload/Node/app bridge. Links cannot replace the app or relax the general browser's file URL ban.
- BrowserService owns marker webviews over app CDP. Renderer creates/closes guests; restore waits for readiness. Inactive agent pages use full-size opacity/pointer-events, never `display: none`. Keys await renderer guest focus. Preserve sequence-free state, registration/active/catalog/icon alignment, bounded evaluations/snapshots, ambiguity checks and native AX hit-test safety. Consent partitions are shared; permissions deny by default. See [browser](docs/architecture/embedded-browser.md).
- TerminalStore owns emulators across pane mounts; output uses `terminal:*`, never React state/Pi events. Preserve utility-process batching/backpressure even when hidden. Resize snapshots completed renders only; no fit per drag frame. Exit permanently disposes emulator/scrollback. Theme cache keeps literal ANSI black/white, 256/RGB colors and mode 2031/OSC notifications. Chrome is beUI.
