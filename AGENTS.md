# AGENTS.md — pi-app

Desktop coding-agent app: the **Pi SDK** kernel (`@earendil-works/pi-coding-agent`, 0.85.x) runs in the Electron main process; the renderer is a fully **beUI**-built interface. Electron (not Tauri) was chosen because the Pi SDK is a Node-only library.

## Golden rule: UI must be beUI-native

**Every UI component comes from beUI.** Do not hand-roll UI primitives (buttons, selects, modals, popovers, disclosures…) and do not introduce other component libraries (shadcn/ui, radix, headlessui, antd…).

- beUI components live in `src/renderer/src/components/motion/` and `src/renderer/src/components/agents/` (plus their `lib/` helpers). Treat them as vendored: don't rewrite them, and don't "fix" registry code in place.
- Vendored files MAY carry deliberate local patches when the registry component cannot express what the app needs. Mark every such edit with a `// local patch (pi-app):` comment, keep it minimal, and put app-level wrappers in `components/app/` when the vendored component stays untouched (e.g. [ThemeButton.tsx](src/renderer/src/components/app/ThemeButton.tsx) wraps the vendored `ThemeToggle`).
- To add a component: `node scripts/beui-add.mjs <slug>` (fetches `https://beui.dev/r/<slug>`, writes each `files[]` entry under `src/renderer/src/<path>`, **never overwrites an existing file**, `--check` reports only; install its listed npm deps separately) or the beUI MCP server's `get_component`. Skip `type: "preview"` files (they land under `components/previews/` and are never imported).
- App glue components live in `src/renderer/src/components/app/` and must be **compositions of beUI primitives** plus Tailwind classes using the theme tokens (`bg-background`, `text-muted-foreground`, `border-border`, `bg-primary`, …) defined in `src/renderer/src/styles.css`.
- UI glyphs come from `lib/icons.tsx`, the single funnel (`IconComponent` / `IconProps`). It is a **per-pack table**: IBM Carbon's line family for the square interface style and HugeIcons' stroke-rounded family for the squircle style — one glyph per pack per semantic name; call sites keep semantic names and never choose a pack. The pack comes from `lib/icon-pack.tsx`'s context, fed by `iconPackOf(uiStyle)` from `lib/ui-style.ts` (`applyUiStyle` writes `data-corners` and `data-icon-pack` together). Carbon is not one grid (16/20/32 px artwork), so the adapter passes the box as `width`/`height` and never forwards `size`; never "fix" a non-32 view box. The `@hugeicons` dependency is intentional (an old guard was deliberately removed) — never restore it. Stroke marks (check/minus/cancel/completion/spinner) live in `lib/animated-icons.tsx`; its square column is app-drawn on purpose. **A status ring is never a pack glyph**: the circle at the right of a tool row — and of every row in the task strip (background tasks, Q&A records, subagents), which all render through the same `ToolResult` — is drawn app-side in [status-ring.tsx](src/renderer/src/lib/status-ring.tsx), the same r=9 / 1.5 stroke circle the todo rows and the sidebar's live spin draw. The pack cannot answer it correctly: the square pack turns `CircleCheck` into Carbon's square `CheckboxChecked` and `Ban` into `SquareSlash`, which squared off these little rings in 直角 mode while every sibling stayed round. Settings controls keep following the pack; a status ring never does. Verify with `node scripts/check-status-ring.mjs`. Provider logos use bundled `@lobehub/icons-static-svg` masks in [ProviderIcon.tsx](src/renderer/src/components/app/ProviderIcon.tsx) — avoid its React package. Run `node scripts/check-icons.mjs` after touching the icon layer (`PI_ICONS_SCREENSHOT_DIR` retains both packs' galleries).
- File-type icon exception: **vscode-icons** for format/framework recognition, behind [FileTypeIcon.tsx](src/renderer/src/components/app/FileTypeIcon.tsx) (shared by file-tree rows and top-level file tabs). Artwork comes from `@iconify-json/vscode-icons` (dev dep) and is **not bundled**: `scripts/prepare-file-icons.mjs` (postinstall/predev/prebuild) writes only the reachable icons as plain SVGs into the generated, gitignored `src/renderer/public/file-icons/`, rendered as `<img src="./file-icons/<name>.svg">` (relative because the packaged renderer loads from `file://`). `lib/file-icons.ts` owns the lookup over the generated `lib/file-icons.map.json`: exact name → name glob × extension → longest matching extension → generic file. The map is generated from vscode-icons' own manifest by `scripts/generate-file-icon-map.mjs` (`npm run icons:file-types`, needs network, commit its output). Folder/navigation/toolbar glyphs stay in the app's icon adapter. Verify with `node scripts/check-file-browser.mjs` and `node scripts/check-icons.mjs`.
- Markdown rendering exception: `react-markdown` in `lib/markdown.tsx` (a renderer, not a UI kit), with the remark plugins in [markdown-plugins.ts](src/renderer/src/lib/markdown-plugins.ts): `remark-gfm`, `remark-cjk-friendly` and `remarkCjkAutolinkTrim`. Code fences render through beUI's `CodeBlock`; all other markdown elements are styled via the components map with beUI tokens.
- The interactive terminal uses `@xterm/xterm` as its screen/input engine (not a UI kit); all terminal chrome is beUI Tabs/Button. `TerminalStore` owns emulator lifetimes outside pane mounts. An exited terminal page shows only its status — no restart button or residual screen; dispose the emulator/scrollback on exit and never recreate it on revisit. Output goes through `terminal:*` IPC, never Pi events or React state. `main/terminal/host.ts` is a separately built Electron utility process that batches PTY output and pauses at a 128 Ki-character unacknowledged high watermark, resuming below 32 Ki — preserve that end-to-end accounting, including while panes are hidden. Terminal colors live in `styles.css` and are resolved/cached by `terminal-theme.ts` (keep ANSI black/white literal, the 256-color cube/RGB untouched); `terminal-color-scheme.ts` adds mode 2031 notifications alongside OSC 10/11. `scripts/prepare-terminal.mjs` restores the macOS spawn-helper's executable bit after install. `TerminalFit` snapshots only a completed render during resize; never reintroduce `fit.fit()` per drag frame. Verify with `node scripts/check-terminal.mjs` after building.

## Golden rule: every user-facing string goes through i18n

The UI ships in **English and 简体中文**; switching lives in Settings → Appearance and applies immediately. When adding or changing ANY user-visible renderer text (labels, placeholders, aria-labels, tooltips, empty/loading/error states):

1. Add the key to **both** `src/renderer/src/i18n/locales/en.ts` (source of truth) and `locales/zh-CN.ts` — the `Messages` type makes a missing/extra key a typecheck error. Keys are flat `domain.key` strings; use `{name}` placeholders for interpolation via `t(key, params)`.
2. Read strings with `const { t } = useI18n()` — never hard-code prose in JSX or template literals, including `aria-label`/`title` attributes.
3. Language names render via `LOCALE_NAMES` in their own language (never translated); add new locales by extending `Locale`, the `dictionaries` map and `LOCALE_NAMES` in `src/renderer/src/i18n/index.tsx`.
4. Known boundary: strings INSIDE vendored beUI components stay English — do not edit vendored files to translate them; pass app-level labels (`summary`, `activeLabel`, `title`, …) through `t()` instead.
5. The main process sends only data over IPC (no prose); compose any user-visible message from the rendered text in the renderer.

## Golden rule: scrollbars are invisible

**No scroll container ever shows scrollbar chrome.** Implemented once, app-wide, in `src/renderer/src/styles.css` (`scrollbar-width: none` on `*` plus `*::-webkit-scrollbar { display: none }`).

- Never style or re-enable scrollbars per element, and never edit a vendored beUI file to hide one. The `scrollbar-hide` utility stays only because vendored components still reference it.
- Because the bar takes no layout space, a scroll container holding focusable inputs needs its own padding (e.g. `p-1`) so focus rings are not clipped.
- Surfaces whose content can overflow use the shared 12px scroll-fade ramp (`useScrollFade` / [FadeScroll.tsx](src/renderer/src/components/app/FadeScroll.tsx)): absent while nothing is hidden, on the edge(s) that actually hide content, landing on a line boundary where a cap applies.

## Continuous corners and elevation

- `styles.css` owns the entire corner scale, and the scale is a **preset**: `:root` carries the square style (every step `0px`); `[data-corners='squircle']` carries the continuous-corner values (`detail` 4px, `inner` 10px, `item`/`control`/`icon` 14px, `card` 20px, `window` 28px, `capsule` 9999px). Both semantic Tailwind classes (`rounded-control`, `rounded-card`, …) and beUI's `rounded-sm`…`rounded-4xl` resolve to this scale. The preset block must stay **below** `:root` (same specificity, wins on source order). `lib/ui-style.ts` owns the preference (`pi-app:ui-style`, default `square`). Use tokens everywhere — no literal pixel radii or numeric `radius` props; `0` is the intentional square edge.
- Native `corner-shape: var(--app-corner-shape)` defaults to `squircle` on every element and pseudo-element, including portals; the base layer falls back to circular arcs in unsupported engines. No SVG masks, observers or per-frame path generation.
- `rounded-full` explicitly means a true circle/capsule and sets `corner-shape: round`; both declarations are `!important` (Tailwind emits `@utility` rules before the sorted radius scale). Reserve it for status/legend dots, activity indicators, loader artwork, ripples, favicon avatars. `rounded-capsule` means the shape **follows the UI style** (avatars, icon-size controls, chips, badges, pill indicators) and is `!important` for the same reason. Selection controls are `rounded-control` **plus `corner-round`** (hard-edged in square, a true circle in squircle); the on-state **mark** keeps radio and checkbox tellable apart (radio = dot; checkbox = style-dependent point / check glyph), text-sized (14px box), carrying `data-checkbox-mark`. **Every on/off control is that checkbox** — the vendored `Switch` is unrendered in both styles. Ordinary text buttons/fields use `rounded-control`; badges `rounded-item`/`rounded-control`; intentionally circular geometry uses `corner-round`; layered surfaces inherit both radius and shape via `rounded-inherit`.
- **Never add a circular `clip-path: inset(... round ...)` to a continuous surface** — it cuts off the squircle. CenterMorphModal / MorphPopover animate the native surface's uniform scale/opacity; reduced motion uses opacity only; Popover's `PresenceGate` releases pointer/focus ownership at exit start.
- Select keeps its edge-flattening motion via a unitless `--select-corner-progress` multiplier (CSS resolves the actual radius per frame); the Tabs indicator takes its radius from the same CSS classes as the tab.
- Floating surfaces use `shadow-overlay`, sourced from one light/dark elevation family. Elevation belongs to floating surfaces only — **no content surface lifts on hover**, and never use Tailwind `shadow-sm|md|lg` as a component drop shadow. Nested diff/review bodies stay `rounded-none` under their single owning frame.
- `node scripts/check-corners.mjs` checks real beUI controls in isolated Electron (geometry, pseudo-elements, live token changes, hit testing, both themes, reduced/instant paths, focus trapping). `PI_CORNERS_SCREENSHOT_DIR` optionally retains screenshots. Also run written-file-preview and terminal checks after changing global geometry.
- Nested confirmation dialogs preserve their parent surface: Rewind keeps the checkpoint panel/diff mounted while a sibling `CenterMorphModal` confirms; suspend the parent's trap, focus Cancel in the child, restore focus with `preventScroll`. Both modal families share `useModalScrollLock` so closing one layer does not unlock another. Portal child `MorphingModal` surfaces out of transformed/clipped parents.

npm run dev          # electron-vite dev (HMR)

Hard rules:

- Renderer **never** imports `electron` or pi packages; it talks only through `window.pi` (typed by `src/renderer/src/env.d.ts` referencing preload).
- New IPC surface = add DTO to `shared/types.ts` + handler in `main/ipc.ts` + method in `preload/index.ts`.
- Pi events flow: `PiManager` emits `pi:event` (serialized via JSON round-trip) → `PiStore.dispatch` → React. Render from `store.messages`; `store.streaming` is the live overlay. High-frequency deltas (`message_update`, `tool_execution_update`) are coalesced in `PiManager.emitEvent` (latest wins, ~33ms flush; ordered events flush first) — keep new hot-path events on that list. **Sequence-free status events** (`context_usage`, `browser:state`, `subagents_update`, sandbox/ask-user metadata pings) must NOT carry `eventSequence` — it would invalidate the renderer's snapshot/event reconciliation.
- **The transcript keeps creation-time order, even for an event that arrives late.** Auto-retry strips the errored assistant round from live state, so a snapshot rebuild has no slot for it and it re-enters `PiStore` later as a plain event; `PiStore.insertByTimestamp` gives it back its slot instead of appending at the live edge. Verify with `node scripts/check-transcript-order.mjs`.
- **`agent_settled` — not `agent_end` — means the run is over.** `agent_end` fires before post-run continuations (auto-retry, auto-compaction, queued messages); only `agent_settled` (and `pi_error`) ends a run.
- **Managed bash process lifetimes are separate from SDK tool calls.** `main/bash/manager.ts` owns processes, bounded tails/logs and persisted task records; `main/pi/bash-tools.ts` registers app-owned `bash`/`bash_task` through `customTools`. `waitMs` is capped by `bashMaxWaitMs` (default 10s; expiry yields the SAME process, while `timeout` kills the tree). `agent_settled` settles SDK calls only, never background commands. Task metadata uses `pi:bash-task` outside the sequenced stream. The `SessionTasks` strip groups Todo / Background tasks / Subagents / Q&A records above the transcript: exactly one panel open, overlay geometry (floats over the transcript, never pushes it), full-bleed edges aligned to the chat column's side lines, all four panels sharing one collapsed-row cap and row rhythm, every row leading with the same `size-4` icon. Every new command must check the notification owner's `canStart` so stop/dispose cannot race a launch.
- **Plan Mode is a branch fact, separate from permissions.** `main/pi/plan-mode.ts` overlays read-only without changing configured `SandboxMode`; switching/approval share its synchronous transition lock and all asynchronous work preparation owns a reservation. `plan-protocol.ts` folds the COMPLETE selected branch; never infer mode or latest submission from compacted messages. The tool gate wraps the SDK's public setter, preserves the app's active base, substitutes full read-only definitions and checks provenance by definition identity (reviewed extension allowlist currently empty). Held execute references recheck admission. Plan shell requires full DSH, never escalates or falls back to host execution. This is a local model-tool file constraint: no network isolation, arbitrary plugin-host sandbox, user-terminal or sibling-session restriction. Child restriction is frozen on dispatch and can only narrow on resume.
- **Plan submission is durable, sealed and explicitly approved.** `submit_plan` alone supplies canonical Markdown (≤128 KiB UTF-8); main owns IDs/revisions/hash. A later awaited `agent.subscribe` runs AFTER SDK message persistence, fsyncs and seals before publishing. Preserve both `shouldStopAfterTurn` AND the public `agent.continue` adapter: SDK 0.85.1's outer loop otherwise drains queued input after submission. Approval fsyncs requested → mode → exact user-entry-linked started before execution; the private opening capability never crosses IPC. Storage/version locks outrank duplicate-success handling. Stop cancels an opening; recovery never replays it. `plan_state_update` has its own per-path seq and NEVER eventSequence. Cards use main-stamped identity, verified document hashes and bounded compaction recovery; export receives only a reference and native Save As chooses the path. See [Plan implementation](docs/plan-mode-implementation.md). Verify `check-plan-mode.mjs` and, after build, `check-plan-mode-ui.mjs` (includes real preload/IPC), plus lifecycle/persistence/queues/tasks/Rewind regressions when shared paths change.
- **Rewind points exist only before user turns.** `main/rewind/recorder.ts` awaits the SDK user `message_start` barrier, then binds the checkpoint to the persisted message entry ID on `message_end`. Never add tool-level, after-turn, resume or background-completion points. Capture is fenced by `tool`/`process`/`subagent` leases; sibling tools queue behind an in-flight snapshot. `main/rewind/engine.ts` uses raw SHA-256 CAS, reviewed plans, before-image quarantine and verified journal phases — do not replace it with Git add/checkout/reset. `CheckoutCoordinator` owns admission across session/tool/process/terminal lifetimes; unresolved recovery fences extension evaluation on startup. Conversation selection persists in an owned `pith_rewind_selection` entry (fsync before commitment); **the sidebar lists a session from its selected branch** (`main/pi/session-branch.ts` reads the fact from the file's tail). Undo/Redo is supported on the latest checkout. Rewind and Review share [ReviewDiff.tsx](src/renderer/src/components/app/ReviewDiff.tsx); keep large rows windowed and preview fetches bounded. Details: [docs/rewind-implementation.md](docs/rewind-implementation.md). Verify with `check-rewind.mjs`, `check-rewind-sdk.mjs`, `check-rewind-ui.mjs` (plus written-file-preview/terminal/task regressions when shared paths change).
- **Rewind coverage is explicit.** `main/rewind/coverage.ts` diagnoses known successful `edit`/`write` paths from the complete selected branch after the checkpoint. Missing originals outside the saved workspace or in exclusions require explicit partial-restore consent (list every skipped path; never touch a skipped path/ancestor/index entry). Persist skipped paths/reasons in the transaction, history and Undo/Redo previews. Never infer shell writes from prose or reconstruct missing originals from tool output. UI: one fixed toolbar row outside the diff scrollport (change count, totals, collapse-all, split restore action); `RewindActions` composes beUI Button/MorphPopover (dropdown chooses a mode, primary executes it); restore mode controls execution, not preview visibility.
- **Single-file Rewind restores only the working file:** immutable child plan from the reviewed token; preserve raw Git staging and conversation; both main and worker enforce files mode; normal journal/backup/overwrite-warning/Undo-Redo remain mandatory. Preview IPC/cache priority: visible bodies, header stats, adjacent prefetch, then totals in batches ≤16; collapsed bodies in the bounded synchronous cache (64 entries / 8 MiB); verify with `check-rewind-preview-cache.mjs` and `check-rewind-ui.mjs`.
- **Todo state belongs to the complete selected branch.** `main/pi/todo-protocol.ts` parses only successful `todo_write` results; `TodoState` restores through `getBranch()` (never `session.messages`/`buildContextEntries`, which omit compacted tasks). Only committed `message_end` results update the projection. Snapshots carry `todos`; compaction changes the transcript without clearing tasks. Empty lists clear active state but retain the immediately preceding list (`retainedItems`). Cancelled ≠ completed; only new writes enforce at most one `in_progress`. Context reminders live only in the SDK's cloned request and never send messages. Verify with `node scripts/check-todos.mjs` and `node scripts/check-bash-task-ui.mjs`.
- **Bash completion uses immediate steer, never follow-up.** `TaskNotifications` waits only for the original bash `toolResult` to enter history, then `sendCustomMessage(..., { deliverAs: 'steer', triggerTurn: true })`. Its outbox acknowledges `message_end`, pins retained records, survives user queue rebuilding and defers replay across the SDK's drain-before-message-start boundary. Stop/Esc pauses notifications BEFORE recalling user queues; delete/rewind/quit clean up process trees; ordinary chat switching and extension reload do not. Do not recover ownership from persisted PIDs. Verify with `node scripts/check-bash-tasks.mjs` and `check-bash-task-ui.mjs`.
- **Subagents are real managed sessions with per-run persistence.** `src/main/pi/subagents/` owns the engine; the SDK has no native subagent support. The parent model calls the `agent` custom tool (gated by the Settings toggle and the active-tool set); each run creates a full child `AgentSession` through PiManager's `createManagedSession` — one registry, one shutdown path. Children get: a frozen tool ceiling (profile ∩ parent active tools at dispatch, `agent` excluded, applied as the create allowlist AND `initializeSession`'s active set — the normal re-activate-everything path must never run for a child), own TodoState/ChangeScopes/TaskNotifications, NO RewindRecorder, and CONDITIONAL extension loading decided at dispatch by the pure, script-checked `ceilingNeedsExtensions` (an extension tool in the ceiling loads extensions; an explore/review ceiling stays extension-free). AGENTS.md context files inherit per the live app setting. The `agent` tool's roster is LIVE (profiles is a getter re-derived per system-prompt build; a Settings edit applies to the next delegation).
  - **Per-run persistence fixes the upstream resume/staleness defects.** Each run appends `pith_subagent_run`/`pith_subagent_result` entries to the CHILD file plus a `pith_subagent_dispatch` entry on the PARENT branch; a result that fails to persist surfaces as a failed run. `readDiskSubagentRuns` pairs results by runId and reads the LAST start entry as current (a resumed session mid-run reads `interrupted`). Roster updates carry a per-parent monotonic `seq`. Terminal status comes from the pure, script-checked `deriveRunOutcome` (`subagents/runtime.ts`): only a USER stop is `aborted`; the runtime's own turn-limit abort is a designed end (`completed` + `limitReached`); an unpersisted result is `failed`. `prompt()` resolving is never sufficient evidence (also check the final message's `stopReason`, abort bookkeeping, caught exceptions). A failed start-entry write fails the dispatch; any open path restores a child's frozen role from disk.
  - **Run completion waits for the child's own background bash** (`agent_settled` on the child is not completion; drain live background tasks until idle, bounded by caps). **Background completions reuse the bash notification discipline** (`SubagentNotifications` in `subagents/notifications.ts`: steer + `triggerTurn`, acknowledge on `message_end`; Stop/Esc/rewind/resend/delete/quit pause it; a two-phase run lease blocks restores and the parent's own snapshots under live runs; `resendMessage`/`deleteSession` await `stopAll` first; deleting a parent trashes its children's files).
  - **Roster wiring.** Progress is throttled (~1s) token/toolUse accumulation; updates ship as sequence-free `subagents_update` events and ride `SessionSnapshotDTO.subagents`. On parent open, `recover()` rebuilds the roster from disk children (interrupted runs show as cards, never auto-woken). The sidebar hides subagent children (`session-filter.ts`; forks carry `parentSessionPath` too and must stay visible). An OPENED child session is read-only (main refuses prompt/resend/queue/model/thinking/fork; composer disabled; `resume` is the sole write admission and refuses a run whose dispatch left the parent's selected branch). Roster payloads are slim by construction (`slimRunForRoster`; rows never carry `writtenFiles[].patch` — those ride the tool result and the completion notice). The transcript's `agent` row names the profile and task instead of the bare tool name. Card/completion meta deliberately omit the localized status word (the vendored row renders its own), except `interrupted`.
  - **A delegation opens BESIDE the chat.** The card's "open session" adds an `agent:<child session path>` tab to the right rail instead of navigating. `PiManager.peekSession(path)` reads the transcript WITHOUT activating it; `SubagentSessionPane` owns its own `PiStore` and renders the app's `ChatView` with action props omitted (they are optional; never pass no-ops). The pane must hand `ChatView` a flex COLUMN (task strip + `MessageScroller` size themselves as flex items). `SidebarPanel`'s fixed-kind registry (`specFor`) must never be asked about a path-keyed tab — path-keyed tabs take their own label/icon before that lookup. Background completions attach as notices (`subagent_completion`) rendered as quiet tool rows, folding into the turn's changed-files list with protocol-aware dedupe (run-scoped results key by runId; legacy cumulative key by child).
  - **Child writes are attributed, not silent.** `derive.ts` extracts successful child edit/write results into bounded `writtenFiles` (64 KiB patch budget; `write` synthesized) riding the tool result details, folding into the parent turn's list via `turn-written-files.ts`. Rewind coverage classifies child writes from every `agent` call after the checkpoint anchor (failed/stopped runs included — outcome never erases committed writes). Evidence order: the PARENT branch's records first (they survive a deleted child); a gone child file is SKIPPED, never a failed scan. Display merges and consent diagnostics share the evidence; restore uses the generic transaction engine.
  - Profiles are Markdown + flat frontmatter in `~/.pi/agent/agents/*.md` (global) and `<cwd>/.pi/agents/*.md` (project shadows global). A `model:` spec that cannot resolve is rejected in preflight with a precise error ([model-spec.ts](src/main/pi/subagents/model-spec.ts)). Tool sets resolve in one order: explicit `tools:` CSV → `tool_preset` from the pi-web-shared preset file (`pi-web-tool-presets.json`, `allow` selections only) → conservative read-only default (`SUBAGENT_READ_ONLY_TOOLS`). An unresolvable preset falls back to read-only and says so; `tools` is NEVER defaulted to `all`. Four starter profiles are written once (marker beside the files, `<agentDir>/agents/.pi-app-defaults-v1.json`); a drifted agent dir HEALS, an intentional deletion is respected; no builtin/custom split (scope is `global | project`). **Settings → Subagents is the subagents' home**: the enable switch and per-parent concurrency limit (default 4, max 16) live there beside every profile as an ordinary file (list/detail, fields, open/reveal, system-prompt preview). New profiles are created in place (`createSubagentProfileFile`, least-privilege starter with NO `tools:` line, description required); a save applies to the very next delegation. The picker's universe is the shared tools catalog with MCP collapsed into ONE whole and namespaced families (`ctx_*`, `browser_*`, `web_*`) collapsed into one tri-state family row each (`lib/subagent-tools.ts`, `toToolEntries` nests families IN PLACE so canonical CSV order never churns); unknown names surface in their own group and are preserved on save; an empty selection cannot be saved; editing a `tool_preset` profile keeps its preset line with the explicit list taking precedence. Input files: ≤8 / 512 KiB / strict UTF-8 / realpath-confined (resolve the workspace root too — macOS `/var` vs `/private/var` misclassifies otherwise). Inherited parent context is JSON with per-part caps, trimmed by dropping whole OLDEST messages under the 50k budget. Verify with `check-subagents.mjs`, `check-subagent-settings.mjs`, `check-subagent-extension-tools.mjs`.
- **The sidebar list is an index, not a rescan.** `PiManager.listSessions` feeds from [session-list.ts](src/main/pi/session-list.ts) (`SessionListIndex`), never `SessionManager.listAll()` per call; rows are cached per file keyed by `(mtimeMs, size)`, open managed sessions derive from the live manager, and rows persist to `<userData>/session-list-cache.json`. ## DSH file sandbox, manual compaction and context menus

**The DSH file sandbox** (`src/main/sandbox/`) confines `bash`/`edit`/`write` to the workspace by default. Three modes — `read-only`, `workspace-write` (the default), `danger-full-access` — resolve through a runner chain in DSH order (seatbelt → bubblewrap → Landlock → Windows ACL → `dependencies-missing`); the optional native helpers resolve through a **computed specifier**. Writable roots are the canonical workspace plus `/tmp` and `os.tmpdir()`; symlink-safe resolution walks the deepest existing ancestor. Bash is confined **before** a task record exists, so a confined mode with no usable runner can never become a "running" task that ran on the host. `edit`/`write` are app-owned tools over the SDK's `EditOperations`/`WriteOperations`, checked per side effect.

- **The mode is per session, not per app.** A custom branch entry (`pith_sandbox_mode`), newest-wins; `AppSettings.sandboxMode` is only the default a new chat starts from. Tools read the live value, so a switch applies from the next tool call.
- **Escalation is one-shot.** `sandbox_permissions` + `justification` on `bash`/`edit`/`write`; a pending queue in main; published as a sequence-free `pi:event` metadata ping; answered from beUI's `ToolApproval` above the composer offering only "Allow once" — deliberately **no standing grant**, and no "always allow" (a deviation from pi-web recorded here so it is not "fixed" later: pi-app also keeps an app-level default for new chats; the broker owns no child processes — `main/bash/manager.ts` already owns them, so the broker supplies only the confined argv/environment/exit classification; the app sends data only, composing escalation prose in the renderer).
- Verify with `node scripts/check-sandbox.mjs` (real Seatbelt, no Electron, fast).

**ask_user_question is a native human-in-the-loop tool**, ported from pi-web onto this app's escalation precedent. [shared/ask-user.ts](src/shared/ask-user.ts) owns the protocol (1–4 questions, 2–4 options each, optional multiSelect, free-text always allowed) plus the defensive normalizers; [main/pi/ask-user.ts](src/main/pi/ask-user.ts) owns the pending registry and the customTool registered in `buildSession` beside `todo_write`. Claude Code semantics: skip/Esc is an explicit cancel whose result tells the model to continue on stated assumptions, never an error; every teardown path settles as cancelled. **Two modes**: `blocking` (default — the call waits) and `async` (returns a receipt at once; the outcome is steered in later by [ask-user-notifications.ts](src/main/pi/ask-user-notifications.ts); an async question does NOT take its call's abort signal; the outcome arrives as an `ask_user_answer` custom message rendered through the same `AskUserResultCard`). The outbox keeps the other completions' rules (delivery waits for the receipt's toolResult in branch; acknowledged by the SDK consuming it; wired wherever the bash and subagent owners are). **Only a real answer repays `triggerTurn`** — a timeout is appended quietly while idle, everything else steers into a live turn.

- **Auto-settle is an engagement deadline, not a stopwatch.** `Settings → General → askUserTimeoutSeconds` (default 120s, 10–3600) arms a timer in `waitForAskUser`; the user's FIRST real interaction cancels it for good (main owns the clock); collapsing deliberately does not report. Timeout settles as `cancelled` with `reason: 'timeout'` (its text and badge say the user never answered); an interrupted run reads `aborted` — three separate reasons because the model is told to behave differently.
- Publication follows the `sandbox_escalation` rule exactly: sequence-free `ask_user` republish on every change, `SessionSnapshotDTO.pendingAskUser` fresh at snapshot time, `askUser:respond` validating answers against the entry's own question list (owner path + id). The renderer's [AskUserPanel.tsx](src/renderer/src/components/app/AskUserPanel.tsx) shares the composer's width contract and shows one question at a time (directional slide, radios auto-advance never auto-submitting, multiSelect waits for an explicit submit, Esc skips and wins over Esc-to-stop; 收起 folds without settling, 关闭 dismisses like Skip). Skip/Esc/关闭 land in a local `sent`/`cancelled` state so the panel reports its own outcome; a new `requestId` resets the local state. A subagent child's questions register under the PARENT's owner path with a `source` badge. **The Q&A record lives in the strip, not the transcript** ([ask-user-records.ts](src/main/pi/ask-user-records.ts) projects every ask on the complete selected branch into `SessionSnapshotDTO.askUserRecords`; the transcript keeps only a compact line naming the first question plus an outcome chip). Verify with `check-ask-user.mjs` and `check-ask-user-ui.mjs`.

**Manual compaction** is a command-palette action and a title-row pocket action (`AgentSession.compact()`), refused while a turn is live (the SDK's manual path aborts the run and never retries it). **A context rewrite renders as a tool row**: [SummaryRow.tsx](src/renderer/src/components/app/SummaryRow.tsx) hosts both kinds — `compaction` and `branch` — through the vendored `ToolResult` (running / settled with collapsed `{tokens} tokens summarized` + lazy markdown expansion / failed carrying the SDK's reason). **The SDK's trailing `<read-files>`/`<modified-files>` sections become real lists** ([summary-files.ts](src/renderer/src/lib/summary-files.ts), fence-aware; the tag text must never reach the body). **`buildTurns` places those summaries by time**, not array order (`placeSummaries` inserts each after every turn older than it; correct with nested compactions; never part of an assistant group). Verify with `check-bash-task-ui.mjs`, `check-context-estimate.mjs`, `check-summary-files.mjs`. It stays out of model context on purpose.

**Context menus are one per surface, never one trigger per row.** A single `ContextMenu` wraps the surface; one handler resolves the target from the DOM (`closest('[data-…]')`); the `ContextMenuContent` is a sibling. Terminal actions route through `terminal:*` IPC. The menu is the portal that is not hidden (Escape is dispatched inside the open one); a right-click resolving no row is `preventDefault`-ed; a transcript menu follows the existing `MessageActions`/`retryFrom`/`forkAt` props. ## Shell layout: three columns, one budget

The native frame uses `main/window-chrome.ts` (`titleBarStyle: 'hidden'`, native traffic lights overlay). `WindowTitlebar.tsx` owns the renderer row; `styles.css` owns its 52px height and platform insets. Today it holds the two SDK command-palette actions — `/compact` (`pi:compact` → `AgentSession.compact()`) and `/reload` (`pi:reload` → re-reads extensions, skills, prompts and context files for every live session) — both refused while the session runs, sharing one handler per action with the palette. `node scripts/check-window-chrome.mjs` (`PI_WINDOW_SCREENSHOT_DIR` retains screenshots).

`src/renderer/src/lib/panel-layout.ts` owns the numbers (min/max per panel, `CHAT_MIN`, `fitPanelLayout`, `clampPanelWidth`, localStorage persistence). The workspace keeps the widths the user **set** (`panelPreference`) apart from what is **on screen** (`fitPanelLayout(preference, viewportWidth, visibility)`) — a narrow window shrinks panels without ratcheting the preference down. Dragging is `PanelResizeHandle` + `useDragResize` (listens on `window`; a press that never dragged toggles the panel). Three rules keep a resize from stuttering (a long session is ~20k elements):

- **A drag renders nothing**: `resizePanels` writes the pair to the two panels as CSS variables directly (no React state), both panels reading them while either strip is pulled; the width commits on release. The dragged panel's ceiling keeps the sibling's floor plus `CHAT_MIN` — the transcript is the one column a drag may not squeeze.
- **Each write goes to that panel's own element**, never to a shared ancestor (a custom property is *inherited*; writing it higher invalidates everything below).
- **The transcript skips offscreen turns** (`content-visibility: auto` on `[data-slot="message-group"] > *`, always on; toggling it per gesture froze the release). The drag overlay exists for the same reason. The right strip straddles both top rules (`-mx-[3px]`) so the boundary lands exactly on the rail's left border.

## Pi SDK facts (learned from the installed package, 0.85.x)

- Read types from `node_modules/@earendil-works/pi-coding-agent/dist/**/*.d.ts`; `pi-ai`/`pi-agent-core` are **nested** under it.
- `ImageContent` is `{ type: "image", data: base64, mimeType }` — the online SDK docs show an older `source`-based shape; trust the installed `.d.ts`.
- Assistant messages have no id — key rows by `role+timestamp+index`.
- Tools used: the seven built-ins `read`, `bash`, `edit`, `write`, `grep`, `find`, `ls` (set explicitly, see the allowlist note above) plus every tool an enabled extension registers (`web_search`/`web_fetch` from Tavily, `mcp`/`mcpScript`/`mcp__*` from the MCP adapter, `ffgrep`/`fffind`/`fff-multi-grep` from pi-fff, the `ctx_*` family from context-mode). `edit` returns a unified diff in `details.patch` (parsed in `lib/diff.ts`); `write` returns no details, so the app synthesizes its diff from the call's `content`.
- Credentials are shared with the `pi` CLI via `~/.pi/agent/auth.json`.
- **Context files (AGENTS.md/CLAUDE.md) are injected as a `<project_context>` block**; discovery loads the global agent dir plus every ancestor directory down to `cwd` (first candidate per dir: `AGENTS.override.md` → `AGENTS.md` → `AGENTS.MD` → `CLAUDE.md` → `CLAUDE.MD`). `noContextFiles` is fixed at loader construction, so the app passes an `agentsFilesOverride` that reads `PiManager.includeContextFiles` **live** — `session.reload()` re-runs it, which is what makes Settings → Prompt → Context files apply to live sessions.
- **Global append prompt lives at `~/.pi/agent/APPEND_SYSTEM.md`** (project-local `.pi/APPEND_SYSTEM.md` is its trusted-project counterpart). Each session caches the built base system prompt, so editing the file does **not** reach a live session until `AgentSession.reload()` — `PiManager.setAppendPrompt` reloads idle sessions and defers streaming ones to `agent_settled`.
- **Resend/retry = `navigateTree(userEntryId)` + re-`prompt`** (the abandoned branch stays in the session tree). It THROWS while streaming and **emits no AgentSession event** — `PiManager.resendMessage` bumps `managed.eventSequence` by hand. When the user message is already the leaf, `navigateTree` no-ops — rewind via `sessionManager.branch(parentId)` / `resetLeaf()` + `agent.state.messages = buildSessionContext().messages` like the SDK does internally.
- **Fork at a message = `SessionManager.open(sourceFile).createBranchedSession(entryId)`** on a separate manager. The SDK mutates the receiver's file/id/branch; never call it on the live source manager (the source would write into the fork, and deleting the fork followed by continuing the source recreates a headerless file). Renderer messages correlate to entries by `role+timestamp` over `buildContextEntries()` (`findMessageEntry`); `scripts/check-session-persistence.mjs` covers it.

## Gotchas

- **Dependency versions are pinned by peer conflicts**: electron-vite 5 supports only vite ^5–7 (NOT vite 8); `@vitejs/plugin-react` must be ^5.2 for vite 7. Don't blindly upgrade.
- **Main entry must build to `out/main/index.mjs`**: electron-vite's lib-mode default emits `.js`. The explicit `rollupOptions.input` + `output: { format: 'es', entryFileNames: '[name].mjs' }` in `electron.vite.config.ts` is load-bearing — keep it.
- If `npm run preview` says "Electron uninstall", run `node node_modules/electron/install.js` (postinstall can be skipped).
- Running `electron out/main/index.mjs` directly uses `~/Library/Application Support/Electron` as userData instead of `pi-app` — prefer `npm run preview`. Settings live at `<userData>/app-settings.json` (shape: `AppSettings` in `src/main/settings.ts`).
- E2E/smoke testing without screen access: launch with `--remote-debugging-port=9222`, then a small Node script over the CDP WebSocket (`Runtime.evaluate`, `Page.captureScreenshot`) — the `scripts/check-*.mjs` suites are built on this.
- beUI components rely on `@/` → `src/renderer/src` alias and on `dark:` = `.dark` class (next-themes); accents are `[data-accent=…]` presets in `styles.css`.
