# AGENTS.md — pi-app

Desktop coding-agent app: the **Pi SDK** kernel (`@earendil-works/pi-coding-agent`) runs in the Electron main process; the renderer is a fully **beUI**-built interface. Electron (not Tauri) was chosen because the Pi SDK is a Node-only library.

## Golden rule: UI must be beUI-native

**Every UI component comes from beUI.** Do not hand-roll UI primitives (buttons, selects, modals, popovers, disclosures…) and do not introduce other component libraries (shadcn/ui, radix, headlessui, antd…).

- beUI components live in `src/renderer/src/components/motion/` and `src/renderer/src/components/agents/` (plus their `lib/` helpers). Treat them as vendored: don't rewrite them, and don't "fix" registry code in place.
- Vendored files MAY carry deliberate local patches when the registry component cannot express what the app needs. Mark every such edit with a `// local patch (pi-app):` comment explaining why, keep it minimal, and put app-level wrappers in `components/app/` when the vendored component stays untouched (e.g. [ThemeButton.tsx](src/renderer/src/components/app/ThemeButton.tsx) wraps the vendored `ThemeToggle`).
- To add a component: fetch it from the beUI MCP server (`get_component`) or the registry `https://beui.dev/r/{slug}` (JSON `files[]` → write each file to `src/renderer/src/<path>`, install its listed npm deps). Skip `type: "preview"` files (they land under `components/previews/` and are never imported by the app).
- App glue components live in `src/renderer/src/components/app/` and must be **compositions of beUI primitives** plus Tailwind classes using the theme tokens (`bg-background`, `text-muted-foreground`, `border-border`, `bg-primary`, …) defined in `src/renderer/src/styles.css`.
- Markdown rendering exception: `react-markdown` in `lib/markdown.tsx` (a renderer, not a UI kit), with the remark plugins in [markdown-plugins.ts](src/renderer/src/lib/markdown-plugins.ts): `remark-gfm`, `remark-cjk-friendly` (CJK emphasis) and `remarkCjkAutolinkTrim` (literal autolinks glued to CJK punctuation). Code fences still render through beUI's `CodeBlock`; all other markdown elements are styled via the components map with beUI tokens.

- The interactive terminal uses `@xterm/xterm` as its screen/input engine (not a UI kit); all terminal chrome is composed from beUI Tabs and Button. `TerminalStore` owns emulator lifetimes outside pane mounts. Inner terminal tabs use beUI segments; top-level tabs keep their underline style. An exited terminal page shows only its status, with no restart button or residual screen; dispose its emulator/scrollback on exit and never recreate it when revisiting the page. Output goes through `terminal:*` IPC, never Pi events or React state. `main/terminal/host.ts` is a separately built Electron utility process: it batches PTY output and pauses at a 128 Ki-character unacknowledged high watermark, resuming below 32 Ki after xterm's write callback. Preserve that end-to-end accounting, including while panes are hidden. `styles.css` also suppresses xterm 6's DOM scrollbar in the same global policy. `scripts/prepare-terminal.mjs` restores the macOS native spawn-helper's executable bit after install; electron-builder unpacks node-pty from asar. Terminal colors live in `styles.css` and are resolved/cached by `terminal-theme.ts`; keep ANSI black/white literal and keep the 256-color cube/RGB output untouched. `terminal-color-scheme.ts` adds mode 2031 notifications alongside xterm’s native OSC 10/11 queries. `TerminalFit` snapshots only a completed render during resize and removes its cover after the replacement frame, avoiding canvas-clear flashes without changing WebGL drawing-buffer behavior; never reintroduce `fit.fit()` on each drag frame. Verify with `node scripts/check-terminal.mjs` after building.

## Golden rule: every user-facing string goes through i18n

The UI ships in **English and 简体中文**; switching lives in Settings → Appearance and applies immediately. When adding or changing ANY user-visible renderer text (labels, placeholders, aria-labels, tooltips, empty/loading/error states):

1. Add the key to **both** `src/renderer/src/i18n/locales/en.ts` (source of truth) and `locales/zh-CN.ts` — the `Messages` type makes a missing/extra key a typecheck error. Keys are flat `domain.key` strings; use `{name}` placeholders for interpolation via `t(key, params)`.
2. Read strings with `const { t } = useI18n()` — never hard-code prose in JSX or template literals, including `aria-label`/`title` attributes.
3. Language names render via `LOCALE_NAMES` in their own language (never translated); add new locales by extending `Locale`, the `dictionaries` map and `LOCALE_NAMES` in `src/renderer/src/i18n/index.tsx`.
4. Known boundary: strings INSIDE vendored beUI components (e.g. ToolResult's "Completed", CodeBlock's "Ready") stay English — do not edit vendored files to translate them; pass app-level labels (`summary`, `activeLabel`, `title`, …) through `t()` instead.
5. The main process sends only data over IPC (no prose); compose any user-visible message from the rendered text in the renderer.

## Golden rule: scrollbars are invisible

**No scroll container ever shows scrollbar chrome.** Scrolling still works; the bar itself is hidden everywhere in the app. This is implemented once, app-wide, in `src/renderer/src/styles.css` (`scrollbar-width: none` on `*` plus `*::-webkit-scrollbar { display: none }`) — its single source of truth.

- Never style or re-enable scrollbars per element (no `::-webkit-scrollbar` rules, no width/thumb/track styling) and never edit a vendored beUI file to hide one. The `scrollbar-hide` utility stays only because vendored components still reference it; app code does not need it.
- Because the bar takes no layout space, a scroll container that holds focusable inputs needs its own padding (e.g. `p-1`) so focus rings are not clipped by the box edge.

## Continuous corners and elevation

- `styles.css` owns the entire corner scale: `--app-radius-detail` (4px), `inner` (10px), `item`/`control`/`icon` (14px), `card` (20px), `window` (28px). Both semantic Tailwind classes (`rounded-control`, `rounded-card`, etc.) and beUI's existing `rounded-sm` through `rounded-4xl` resolve to this scale. Use tokens in inline styles/animation targets too; no literal pixel radii or numeric `radius` props. `0` remains the intentional square edge.
- Native `corner-shape: var(--app-corner-shape)` defaults to `squircle` on every element and before/after pseudo-element, including portals. The base-layer rule gracefully falls back to circular arcs in unsupported engines. No SVG masks, extra observers or per-frame path generation.
- `rounded-full` explicitly means a true circle/capsule and sets `corner-shape: round`, including Tailwind pseudo-element variants. Both declarations are `!important`: Tailwind emits custom `@utility` rules before its own sorted radius scale, so a control carrying both `rounded-full` and a semantic radius (`size="icon"` adds `rounded-icon`) would otherwise win back a 14px radius and lose the circle. Reserve it for switch tracks/thumbs, radios, avatars, status/loader dots, ripples, deliberately circular icon controls and the explicitly named Tabs `pill` variant. Ordinary text buttons/fields use `rounded-control`, and badges use `rounded-item`/`rounded-control`. For another intentionally circular geometry use `corner-round`. Layered surfaces use `rounded-inherit` to inherit **both** radius and shape.
- **Never add a circular `clip-path: inset(... round ...)` to a continuous surface.** It cuts off the squircle even at rest. CenterMorphModal and MorphPopover animate the native surface's uniform scale/opacity, keeping border, overflow clipping and shadow consistent throughout entry/exit. Reduced motion uses opacity only; `instant` previews keep their no-animation path. Popover's `PresenceGate` releases pointer/focus ownership at the start of exit.
- Select retains its edge-flattening motion using a unitless `--select-corner-progress` multiplier. CSS resolves the actual radius from the theme token on every frame; do not replace it with Motion-resolved fixed pixels. Tabs' moving indicator takes its radius from the same CSS classes as the tab, with no inline override.
- Floating surfaces use `shadow-overlay`, sourced from one light/dark elevation family. Keep real borders/focus rings separate; don't add an extra hairline to the shadow or a component-specific blur/drop-shadow. Nested diff/review bodies remain `rounded-none` under their single owning frame.
- `node scripts/check-corners.mjs` checks actual beUI controls in isolated Electron: continuous/circular geometry, pseudo-elements, inherited backgrounds, live token changes, per-frame native corner hit testing, both themes, reduced/instant paths, focus trapping/restoration and exit cleanup. `PI_CORNERS_SCREENSHOT_DIR` optionally retains the gallery/dialog screenshots. Also run the written-file-preview and terminal checks after changing global geometry.

- Nested confirmation dialogs preserve their parent surface. Rewind keeps the checkpoint panel and diff DOM mounted while a sibling `CenterMorphModal` confirms single-file, batch, partial, Undo or Redo actions. Suspend the parent's interaction/focus trap, focus Cancel in the child, and return focus with `preventScroll` when cancelling; single-file preview loading must not remove the main diff. Both beUI modal families share `useModalScrollLock` so closing one layer does not unlock another, and unmounting all layers releases the lock. Portal child `MorphingModal` surfaces out of transformed/clipped parents (as in `CopyConfigDialog`).

## Commands

```bash
npm run dev          # electron-vite dev (HMR)
npm run typecheck    # tsc for main+preload AND renderer (always run before done)
npm run build        # production build to out/
npm run preview      # run the built app
```

No test framework. Verification is manual/CDP (see Gotchas). Always `npm run typecheck && npm run build` after changes.

Hard rules:

- Renderer **never** imports `electron` or pi packages; it talks only through `window.pi` (typed by `src/renderer/src/env.d.ts` referencing preload).
- New IPC surface = add DTO to `shared/types.ts` + handler in `main/ipc.ts` + method in `preload/index.ts`.
- Pi events flow: `PiManager` emits `pi:event` (serialized via JSON round-trip) → `PiStore.dispatch` → React. Render from `store.messages`; `store.streaming` is the live overlay. High-frequency deltas (`message_update`, `tool_execution_update`) are coalesced in `PiManager.emitEvent` (latest wins, ~33ms flush; ordered events flush first) — keep new hot-path events on that list.
- **`agent_settled` — not `agent_end` — means the run is over.** `agent_end` fires before post-run continuations (auto-retry, auto-compaction, queued messages), so clearing streaming/busy state or the sidebar spinner there lies while work continues. Only `agent_settled` (and `pi_error`) ends a run.
- **Managed bash process lifetimes are separate from SDK tool calls.** `main/bash/manager.ts` owns processes, bounded tails/logs and persisted task records; `main/pi/bash-tools.ts` registers app-owned `bash`/`bash_task` through `customTools`, overriding built-in/extension names while preserving SDK tool hooks and shell settings. `waitMs` is capped by the app's `bashMaxWaitMs` (default 10s); expiry yields the SAME process, while `timeout` kills its process tree. `agent_settled` only settles SDK calls, never background commands. Task metadata uses `pi:bash-task`, outside the sequenced transcript stream; output is read on demand. Renderer rows and folded group counts consult the independent task store. `SessionTasks` groups the Todo and Background tasks entries above the transcript; exactly one panel is open, clicking the active entry closes it, and changing sessions resets its selection. Its expanded list floats over the transcript (an `absolute inset-x-4 top-full` wrapper with `rounded-card` + `shadow-overlay`), never in the flex flow: opening it must not push or scroll the page, and it owes an overlay's dismiss gestures (`useDismiss` for outside presses plus a capture-phase Escape that `preventDefault`s so it closes instead of stopping the run). The elevation rides that wrapper, not the panel: `AgentDisclosure`'s rectangular rest clip-path (`inset(0 0 0% 0)`) squares any shadow drawn on the element it clips. Its height is a whole number of collapsed rows (`max-h-[16.5rem]` = six 36px rows plus padding and gaps), so the resting list never cuts a row in half; the row a scroll actually cuts fades out through BeUI's capped-list mask (the same 12px ramp `AgentActivity` uses) instead of ending in a hard chop. Every new command must check the notification owner's `canStart` so stop/dispose cannot race another launch.
- **Rewind points exist only before user turns.** `main/rewind/recorder.ts` awaits the SDK user `message_start` barrier, then binds the checkpoint to the actual persisted message entry ID on `message_end`; timestamps and nearest-point guesses are insufficient. Never add tool-level, after-turn, resume or background-completion points. File transactions remain durable independently of visible timepoints: `main/rewind/engine.ts` uses raw SHA-256 CAS, a fixed reviewed plan, before-image quarantine and verified journal phases, including index bytes and staged-only Git objects. Do not replace it with Git add/checkout/reset. `CheckoutCoordinator` owns admission across actual session/tool/process/terminal lifetimes; unresolved recovery must fence extension evaluation on startup. Conversation selection is persisted with an owned `pith_rewind_selection` entry and fsync before commitment; lost replies reconcile the journal before compensation. The latest checkout operation supports Undo/Redo, preserving unrelated paths. UI overwrite warnings conservatively cover every changed file/staging item because writer provenance is unknown; explicit force confirmation still requires a fresh preview and verified safety backup. It never bypasses active work, backup corruption or unresolved conflicts. Rewind and Review share `components/app/ReviewDiff.tsx` for headers, collapse controls and diff bodies; keep large rows windowed against the page, fetch only nearby preview bodies, and bound the IPC/cache. Settings text and all errors are bilingual. Details and limits: [docs/rewind-implementation.md](docs/rewind-implementation.md). Verify with `check-rewind.mjs`, `check-rewind-sdk.mjs`, `check-rewind-ui.mjs`, plus written-file-preview, terminal and task regressions when their shared paths change.
- **Rewind coverage is explicit.** `main/rewind/coverage.ts` diagnoses known successful `edit`/`write` paths from the complete selected SDK branch after the checkpoint. Missing originals outside the saved workspace or in exclusions require explicit partial-restore consent: list every skipped path, then restore only the immutable preview’s backed-up portion. The renderer sends only `skipUncovered`; main takes the omission list from the reviewed token, and the worker also checks consent. Never touch a skipped working path, ancestor or index entry; overlapping plans, stale previews, corruption and recovery fences remain hard errors. Persist skipped paths/reasons in the transaction, history and Undo/Redo previews, and distinguish partial success. Files-only with no restorable changes cannot report success; combined restore may explicitly leave files alone while restoring the conversation. Conversation-only and independently backed-up single-file actions do not grant partial batch consent. Never turn an empty standalone workspace backup into a claim that outside edits did not happen, infer shell writes from prose, or reconstruct missing originals from tool output. This diagnostic does not widen the pre-turn snapshot boundary. Keep change count, full-preview line totals, collapse-all, the split restore action and an icon-only backup information popover in one fixed toolbar row outside the diff scrollport, with no bottom bar; scrollport padding must not displace sticky Review file headers. Sidebars prioritize turn content over timestamp and backup count. History rows prioritize the file/scope and distinguish completed Restore, Undo and Redo from failure states. Previewable entries are whole beUI Buttons with selection keyed by preview.operationId; keep older entries passive and skipped-path disclosures outside those buttons. No separate sidebar preview buttons: row activation only previews, and the fixed toolbar executes. `RewindActions` composes beUI Button/MorphPopover: default to conversation-only; the dropdown only chooses a mode, and the primary action executes it. File-changing alternatives show overwrite/blocking warnings. Undo/Redo keep their saved mode. Nested popovers own Escape before the outer modal, restore focus, stay mutually exclusive and do not resize the toolbar. Restore mode controls execution, not preview visibility: all modes show the same file diffs, totals and collapse controls. Conversation-only copy must distinguish this reference preview from its conversation-only action. Uncovered paths warn before a partial restore without hiding independently backed-up file previews.
- **Single-file Rewind restores only the working file.** Derive its immutable child plan from the reviewed token; preserve raw Git staging and conversation, add only required missing parent directories, and reject ancestor-file replacement. Main and worker both enforce files mode. The normal journal, backup verification, overwrite warning and Undo/Redo remain mandatory; history carries the path. Staging and directory headers must not offer a misleading single-file action. Checkpoint headers opt out of path tooltips and fetch independent raw-blob numstat even when collapsed; do not count a truncated patch. Stats and bodies share three prioritized IPC slots: visible bodies, header stats, adjacent prefetch, then totals in batches of at most 16. Totals cover every worktree/index entry beyond pagination, exclude binary line counts, and never publish partial or stale results. Keep collapsed bodies in the bounded synchronous cache (64 entries / 8 MiB UTF-16 eviction budget, nearby active entries pinned), release offscreen parsed DOM, and recheck viewport geometry when queued fetches start. Layout changes must refresh both nearby visibility and virtual row windows before paint; a preceding collapse need not cause a resize/scroll event. Verify cache priority/admission/lifetimes with `check-rewind-preview-cache.mjs` and slow-IPC frame probes with `check-rewind-ui.mjs`. Keep the beUI modal context stable between confirmation and preview so focus returns to the triggering file action.

- **Todo state belongs to the complete selected branch.** `main/pi/todo-protocol.ts` parses only successful `todo_write` results and always returns sanitized data; legacy `pi-web-todo` details remain readable. `TodoState` in `main/pi/todo.ts` owns the per-session projection, restoring through `getBranch()` (never `session.messages` or `buildContextEntries`, which omit compacted tasks). The app registers `todo_write` as a custom tool plus a hidden inline context extension. Only committed `message_end` results update the projection; `execute` and `tool_result` are too early because other extensions can reject or transform them. Snapshots carry `todos`, and sequenced `agent_start`/result events carry changes into `PiStore`; compaction changes the transcript without clearing tasks. Explicit IDs survive renames/reordering; omitted IDs reuse matching tasks, and legacy identities are deterministic. Empty lists clear active state but retain the immediately preceding list (`retainedItems`) for UI review regardless of completion status; reconstruction derives it from the selected branch, reminders ignore it, and a new nonempty list replaces it. Retained rows preserve their original statuses under a localized history label, with no running animation even during a later turn. Cancelled tasks are not completed, and only new writes enforce at most one `in_progress`. Retries restore after both SDK navigation and the manual leaf rewind. Context reminders live only in the SDK's cloned request, handle custom completion/summary tails, and never send messages or wake an extra turn. Activity epochs prevent a same-batch todo from acknowledging unseen tool results. The beUI `TodoList` uses its minimal marked `headerless` patch under `SessionTasks`; idle progress is stationary without rewriting saved status. `node scripts/check-todos.mjs` covers the real SDK, persistence, branches, custom wakeups and snapshot races; `node scripts/check-bash-task-ui.mjs` covers the shared panels, geometry, keyboard/focus, locales and pause/clear behaviour.

- **Bash completion uses immediate steer, never follow-up.** `TaskNotifications` waits only for the original bash `toolResult` to enter history, then uses `sendCustomMessage(..., { deliverAs: 'steer', triggerTurn: true })`; the SDK consumes it at the next model/tool boundary or wakes an idle session. Its outbox acknowledges `message_end`, pins retained records, survives user queue rebuilding, and defers replay across the SDK's drain-before-message-start boundary to avoid duplicates. User prompt preflight blocks automatic idle wakeups until the SDK owns the run. Stop/Esc pauses notifications BEFORE recalling user queues, stops the session's commands, and prevents old completions from waking a resumed run. Delete, rewind and quit clean up process trees; ordinary chat switching and extension reload do not. Do not recover ownership from persisted PIDs. Completion custom messages remain tool passages in session search (`includeDetails`), not conversation prose. Verify with `node scripts/check-bash-tasks.mjs` and `node scripts/check-bash-task-ui.mjs`.

- **Sidebar membership is immutable through reordering.** `AISidebar`'s marked `canDrag`/`canMove` patch checks pointer, keyboard and menu paths before its optimistic tree update. App policy in `lib/session-sidebar.ts` accepts only before/after between real sessions with the same cwd and pinned status; project roots, section headers, show-more rows, root drops and nesting are forbidden. Pins and manual ordering are presentation preferences in `pi-app:session-sidebar:v1` localStorage, never SDK/session-file edits. Reordering uses all group sessions (including paginated-out rows); background activity must not undo it. Pinning moves a row to the virtual pinned section; unpinning restores its project/order.
- **A projectless chat still has a cwd.** `main/pi/default-workspace.ts` owns the stable `<userData>/workspace` directory; `init()`/`newSession()` without a cwd use it. Global New chat is projectless; a project's + passes its cwd explicitly. Never add the internal directory to known projects. Snapshots/summaries/search hits carry `projectless` for renderer chrome, while `cwd` remains available to tools, attachments and markdown. Hide this path in the header, sidebar and search groups; persisted settings `cwd: null` resumes the internal workspace on boot.
- **Session-wide numbers come from the SDK, never from summing `session.messages`.** `AgentSession.getSessionStats()` aggregates every session entry (messages compacted out of context and tool-result usage included) → `sessionCost`/`cacheHitRate`; `getContextUsage()` is only the live context ring. The ring must keep moving *while* a turn runs, so `PiManager` polls every live session every 2s and pushes a sequence-free `context_usage` event whose payload adds the in-flight partial's `estimateTokens()` (the SDK only counts COMPLETED messages). Don't give that event an `eventSequence` — that would invalidate the renderer's snapshot/event reconciliation — and don't stage the payload onto `PiState` directly: it has to go through `PiStore.setContextUsage` so the shell slice the composer reads is rebuilt with it.
- **`ChatMessage` mirrors the SDK's full agent-message union** (user/assistant/toolResult plus `compactionSummary`/`branchSummary`/`bashExecution`/`custom`) — a session is written by the app, the pi CLI and extensions, so every role must have a transcript row instead of being dropped.
- **Thinking levels are model-derived**: use `AgentSession.getAvailableThinkingLevels()` (it gates `xhigh`/`max` on `thinkingLevelMap` and returns `['off']` for non-reasoning models). Never hardcode a level list.
- **Session search stays off the main/renderer threads.** `SessionSearch` owns the separately built `session-search-worker.mjs`; its SQLite FTS5 index uses encoded Unicode character/bigram tokens for candidates, then verifies literal normalized substrings before counting/pagination. The complete match set is grouped by full `cwd` (not basename), folder groups by their newest (or oldest, for `sort: 'oldest'`) matching activity, and sessions by `modified` in that same direction before LIMIT/OFFSET; never group only a page of a globally time-sorted result set. The renderer search button opens beUI `CenterMorphModal`, which owns focus/escape/portal behavior; titles and conversation prose are always searched together (no mode selector or title-match badge). With an empty query the modal lists every sidebar session grouped and ordered by activity, showing titles only; matching excerpts appear after typing. Keep rows and header compact. Folder headers use beUI buttons plus `AgentDisclosure`, with larger labels and indented session rows. Collapse state is keyed by full cwd across queries/pagination, and Enter must skip collapsed sessions. Title overflow uses a conditional CSS mask via the shared `useOverflowFade` observer, never ellipses or a synchronous width scan of offscreen rows; query polling only runs while that modal is open. Do not cap candidates before verification or replace this with SDK `allMessagesText` (it omits tools and older entry kinds). Search reads saved JSONL across all branches, including pre-compaction history; it excludes image payloads and hidden extension state. `session-search-passages.ts` preserves each content block and its source: default full text searches user/assistant prose, visible custom messages and summaries, while `includeDetails` opts into tool calls/results, thinking and inlined file attachments. Never flatten tool/attachment text into dialogue — a DOM dump or a read of another session can contain its title. Excerpts prefer conversation prose and carry `snippetSource`/`snippetToolName`; phrase verification and snippets share the same block boundaries. Separate conversation/all-content FTS candidates keep normal queries independent of large tool logs. Bump `INDEX_VERSION` whenever indexed semantics/schema change so existing databases rebuild. Size/mtime/ctime/inode checks refresh changed files, and malformed files remain retryable with internal incomplete-result diagnostics; the search panel never displays indexing, search or open-failure errors. Keep successful results while quietly retrying transient search failures, and do not label a failed request as a successful zero-hit search. Persist incomplete/failure fingerprints so unchanged bad files are not reparsed on each poll; changed files and transient I/O failures retry. `scripts/check-session-search.mjs` exercises accuracy, persistence, mutations and a synthetic performance corpus without touching real sessions.
- **Bridge SDK callbacks whole**: auth prompts/notifies (`AuthPrompt.signal`, device-code `verificationUri`, `instructions`) and `compaction_end` payloads carry data the UI needs; forward them rather than re-deriving or dropping them.
- User messages sent through the composer are mirrored optimistically (`__optimistic` flag) and replaced on the real `message_end`. A send the renderer believed idle can still be queued as a steer (race before `agent_start`), so the replacement path also drops a matching echo that is no longer the tail (compare on prose with `<file>` blocks stripped).
- **Queued steer/follow-up messages are mirrored app-side — the SDK exposes only their text.** `AgentSession.getSteeringMessages()`/`clearQueue()` return `string[]`; image bytes live solely in the agent's private queue, so recall/promote/remove would silently drop them. `PiManager.queueMirror` holds `{ text (file blocks inlined, templates expanded), originalText (user draft), images, filePaths }` per item and is reconciled on every `queue_update`. Reconciliation must mirror the SDK's shrink semantics exactly — delivery removes the FIRST occurrence (`indexOf`+`splice`) — and resolve unknown texts against `pendingQueuePayloads`, newest first. That stash is a LIST, not a slot: an enqueue can yield inside `session.prompt()` (a `/` command, an input extension), so two prompts can overlap and each `finally` may only remove its own. `queueAction` rebuilds with `clearQueue()` + `session.steer(item.text, item.images)` inside the `queueRebuilding` window, which swallows the SDK's intermediate `queue_update`s so exactly one final state is emitted. Base64 images never ride `pi:event`: `QueuedItemDTO` carries counts only, and full payloads return through `clearQueue()` (`RecalledItemDTO`).
- **`abort()` does not clear the SDK queues** (the docstring's `clearQueue()` is for exactly this). Stop/Esc must recall the queued messages into the composer *before* aborting, or a stray steer hijacks the next run's opening. Esc-to-stop is a `window` listener while `busy`: overlays win first (React handlers via `defaultPrevented`, `CenterMorphModal` via its `aria-modal` dialog), and `escapeStopsRun` turns it off under full-page Settings/auth surfaces.
- **Every image on screen opens the same preview overlay.** `ImagePreviewProvider` (mounted in `App.tsx`) exposes `useImagePreview()`; composer attachments, user/custom bubble images and markdown images (`PreviewThumb` in [ImagePreview.tsx](src/renderer/src/components/app/ImagePreview.tsx)) all funnel into it, and the overlay itself is beUI's vendored `CenterMorphModal`. Markdown sources are workspace paths, resolved to data URLs (plus their absolute path for “open file”) by [markdown.tsx](src/renderer/src/lib/markdown.tsx).
- Settings are shared through `AppSettings` (`{ cwd, folders, contextFiles, disabledExtensions }`): the active `cwd` is what the file index / sessions / bash run in; `folders` is the sidebar's known list; `contextFiles` toggles injection of AGENTS.md/CLAUDE.md context files (default true); `disabledExtensions` holds the resolved paths of extensions switched off in Settings → Extensions (app-local — the pi CLI's own package config is untouched). Deleting a project moves its sessions to the OS trash and forgets the folder ([deleteFolderSessions](src/main/pi/manager.ts:231)).

## Shell layout: three columns, one budget

The native frame uses `main/window-chrome.ts` (`titleBarStyle: 'hidden'`, native traffic lights/controls overlay). `WindowTitlebar.tsx` owns the renderer row shared by Workspace, Settings and startup; `styles.css` owns its 52px height and platform control insets. Keep the native overlay height/traffic-light position aligned with that row. The three workspace columns are siblings in the flex row **below** it, so the left navigation and right tools share the full remaining height. Never reintroduce a second conversation header for model information (the composer already owns the model picker). Title-row buttons and the project-path tooltip opt out of native dragging. Visible modal dialogs disable title dragging; hidden mobile dialogs must not. The mobile sidebar reserves the title-row height so its first action clears native controls. Theme changes use the typed `window:setTheme` bridge; renderer code never imports Electron. `node scripts/check-window-chrome.mjs` exercises the built renderer in an isolated profile with synthetic sessions; `PI_WINDOW_SCREENSHOT_DIR` retains screenshots.

`src/renderer/src/lib/panel-layout.ts` owns the numbers (min/max per panel, `CHAT_MIN` for the transcript, `fitPanelLayout`, `clampPanelWidth`, localStorage persistence). The workspace keeps the widths the user **set** (`panelPreference`) apart from what is **on screen** (`fitPanelLayout(preference, viewportWidth, visibility)`), so a narrow window shrinks the panels without ratcheting the preference down — widening it again brings back what the user chose. Dragging is `PanelResizeHandle` + `useDragResize`, which listens on `window` rather than using `setPointerCapture` (a 6px strip is left immediately, and capture is not honoured by every input path). The strip sits *outside* the panel as a flex sibling: the sidebar's own panel clips its content (which is exactly why the vendored rail only had a 2px hit area), and a press that never dragged toggles the panel, replacing that rail. The right rail folds itself when its last tab closes; the transcript's changed-files `Review` action opens it and selects the turn.

Three things there are load-bearing for a resize that does not stutter (a long session is ~20k elements, and a naive drag measured 40 dropped frames per gesture):

- **A drag renders nothing.** `resizePanels` writes the pair to the two panels as CSS variables directly (no React state), so only the panels and the transcript reflow; the width is committed to `panelPreference` on release, when the drag is over.
- **Each write goes to that panel's own element**, never to a shared ancestor: a custom property is *inherited*, so writing it higher up invalidates the computed style of everything below (~25k elements per pointermove — 0.8s of style recalc for one drag).
- **The transcript skips offscreen turns** (`content-visibility: auto` on `[data-slot="message-group"] > *`, in `styles.css`). Without it, re-wrapping every turn per frame is the whole cost; with it, layout during a drag is ~0. It is deliberately always on: toggling it for the gesture made the browser lay out every skipped row at once on release — a ~120ms freeze at the end of each drag. The drag overlay (`fixed inset-0`, while a gesture runs) exists for the same reason: the obvious `body[data-panel-resizing]` cursor/user-select rule invalidated the whole document's style at both ends of the drag.

## Pi SDK facts (learned from the installed package, 0.85.x)

- Read types from `node_modules/@earendil-works/pi-coding-agent/dist/**/*.d.ts`; `pi-ai`/`pi-agent-core` are **nested** under it (`.../pi-coding-agent/node_modules/@earendil-works/`).
- `ImageContent` is `{ type: "image", data: base64, mimeType }` — the online SDK docs show an older `source`-based shape; trust the installed `.d.ts`.
- Assistant messages have no id — key rows by `role+timestamp+index`.
- Tools used: the seven built-ins `read`, `bash`, `edit`, `write`, `grep`, `find`, `ls` (set explicitly, see the allowlist note above) plus every tool an enabled extension registers (`web_search`/`web_fetch` from Tavily, `mcp`/`mcpScript`/`mcp__context7` from the MCP adapter). `edit` returns a unified diff in `details.patch` (parsed in `lib/diff.ts` → beUI `FileDiff` lines); `write` returns no details, so the app synthesizes its diff from the call's `content`.
- Credentials are shared with the `pi` CLI via `~/.pi/agent/auth.json`.
- **Context files (AGENTS.md/CLAUDE.md) are injected as a `<project_context>` block**; discovery loads the global agent dir plus every ancestor directory down to `cwd` (first candidate per dir: `AGENTS.override.md` → `AGENTS.md` → `AGENTS.MD` → `CLAUDE.md` → `CLAUDE.MD`). `noContextFiles` is fixed at loader construction, so the app instead passes an `agentsFilesOverride` that reads `PiManager.includeContextFiles` **live** — `session.reload()` re-runs it, which is what makes Settings → Prompt → Context files apply to live sessions.
- **Global append prompt lives at `~/.pi/agent/APPEND_SYSTEM.md`** (the project-local `.pi/APPEND_SYSTEM.md` is its trusted-project counterpart). `DefaultResourceLoader` reads it at load/reload time, and each session caches the built base system prompt, so editing the file does **not** reach a live session until `AgentSession.reload()` — `PiManager.setAppendPrompt` reloads idle sessions and defers streaming ones to `agent_settled`.
- **Resend/retry = `navigateTree(userEntryId)` + re-`prompt`** (same file; the abandoned branch stays in the session tree). Targeting a user message drops it and everything after, and returns its text as `editorText`. It THROWS while streaming, and **emits no AgentSession event** — `PiManager.resendMessage` bumps `managed.eventSequence` by hand so the returned snapshot isn't mistaken for one the renderer already has. When the user message is already the leaf (a run that died before any assistant output) `navigateTree` no-ops — rewind via `sessionManager.branch(parentId)` / `resetLeaf()` + `agent.state.messages = buildSessionContext().messages` like it does internally.
- **Fork at a message = `SessionManager.open(sourceFile).createBranchedSession(entryId)`** on a separate manager. The SDK mutates the receiver's file/id/branch; never call it on the live source manager. Otherwise the source writes into the fork, and deleting that fork followed by continuing the source recreates a headerless file. The fork ends at the selected entry with `parentSession` pointing back; `scripts/check-session-persistence.mjs` covers independent writes and delete-fork/continue-source. Renderer messages are correlated to entries by `role+timestamp` over `buildContextEntries()` (`findMessageEntry`).

## Gotchas

- **Dependency versions are pinned by peer conflicts**: electron-vite 5 supports only vite ^5–7 (NOT vite 8); `@vitejs/plugin-react` must be ^5.2 for vite 7. Don't blindly upgrade.
- **Main entry must build to `out/main/index.mjs`**: electron-vite's lib-mode default emits `.js`. The explicit `rollupOptions.input` + `output: { format: 'es', entryFileNames: '[name].mjs' }` in `electron.vite.config.ts` is load-bearing — keep it.
- If `npm run preview` says "Electron uninstall", run `node node_modules/electron/install.js` (postinstall can be skipped).
- Running `electron out/main/index.mjs` directly uses `~/Library/Application Support/Electron` as userData instead of `pi-app` — prefer `npm run preview`. Settings live at `<userData>/app-settings.json` (`{ cwd, folders }`).
- E2E/smoke testing without screen access: launch with `--remote-debugging-port=9222`, then a small Node script over the CDP WebSocket (`Runtime.evaluate`, `Page.captureScreenshot`) — real model calls cost fractions of a cent on locally configured providers.
- beUI components rely on `@/` → `src/renderer/src` alias and on `dark:` = `.dark` class (next-themes); accents are `[data-accent=…]` presets in `styles.css`.
- Vendored beUI edits must stay marked `// local patch (pi-app)` and minimal (see above) — they are the one exception to "treat beUI as vendored".
- All process code is ESM (`"type": "module"`); preload requires `sandbox: false` in the BrowserWindow.
