# AGENTS.md — pi-app

Desktop coding-agent app: the **Pi SDK** kernel (`@earendil-works/pi-coding-agent`) runs in the Electron main process; the renderer is a fully **beUI**-built interface. Electron (not Tauri) was chosen because the Pi SDK is a Node-only library.

## Golden rule: UI must be beUI-native

**Every UI component comes from beUI.** Do not hand-roll UI primitives (buttons, selects, modals, popovers, disclosures…) and do not introduce other component libraries (shadcn/ui, radix, headlessui, antd…).

- beUI components live in `src/renderer/src/components/motion/` and `src/renderer/src/components/agents/` (plus their `lib/` helpers). Treat them as vendored: don't rewrite them, and don't "fix" registry code in place.
- Vendored files MAY carry deliberate local patches when the registry component cannot express what the app needs. Mark every such edit with a `// local patch (pi-app):` comment explaining why, keep it minimal, and put app-level wrappers in `components/app/` when the vendored component stays untouched (e.g. [ThemeButton.tsx](src/renderer/src/components/app/ThemeButton.tsx) wraps the vendored `ThemeToggle`).
- To add a component: fetch it from the beUI MCP server (`get_component`) or the registry `https://beui.dev/r/{slug}` (JSON `files[]` → write each file to `src/renderer/src/<path>`, install its listed npm deps). Skip `type: "preview"` files (they land under `components/previews/` and are never imported by the app).
- App glue components live in `src/renderer/src/components/app/` and must be **compositions of beUI primitives** plus Tailwind classes using the theme tokens (`bg-background`, `text-muted-foreground`, `border-border`, `bg-primary`, …) defined in `src/renderer/src/styles.css`.
- UI glyphs use **Lucide** through `lib/icons.tsx` (`IconComponent` / `IconProps`), including beUI internals and registry previews. App code imports from that adapter; a newly vendored beUI component may instead keep its native `lucide-react` imports, since it is the same pack. Add explicit, tree-shakable mappings there — the adapter maps semantic app names onto Lucide artwork, and ten of them deliberately differ from Lucide's current spelling for the same shape (`BookDownload`→`BookDown`, `Chart`→`ChartColumn`, `Chat01`→`MessagesSquare`, `CommandLine`→`TerminalSquare`, `Dashboard`→`LayoutDashboard`, `InstallingUpdates`→`PackageOpen`, `MusicNote`→`Music`, `SourceCode`→`SquareCode`, `Subtitle`→`Captions`, `TextFont`→`Type`). Keep Lucide's native 2px stroke unless a caller needs a weight override, and review arrow semantics: Lucide's `ArrowUp`/`ArrowDown`/`ArrowLeft`/`ArrowRight` include a shaft. `lib/animated-icons.tsx` sources its check/minus/cancel/completion/spinner geometry from the same pack — rendering each node by its tag, because the completion mark is a circle plus a path — while preserving beUI drawing and reduced-motion transitions. Actual progress rings and procedural loader effects remain data/animation geometry. Provider logos use bundled `@lobehub/icons-static-svg` masks in `ProviderIcon.tsx`; avoid its React package, which brings other UI/icon dependencies. Run `node scripts/check-icons.mjs` after changing the icon layer; `PI_ICONS_SCREENSHOT_DIR` retains the light/dark gallery.
- File-type icon exception: the user chose **vscode-icons** for format/framework recognition. Keep it behind `components/app/FileTypeIcon.tsx`, shared by file-tree rows and top-level file tabs, with automatic special-filename/extension mapping and a generic fallback. Folder/navigation/toolbar glyphs stay in the Lucide adapter. Artwork comes from `@iconify-json/vscode-icons` (dev dependency) and is **not bundled**: `scripts/prepare-file-icons.mjs` (postinstall/predev/prebuild) writes only the reachable icons as plain SVGs into the generated, gitignored `src/renderer/public/file-icons/`, and the component renders `<img src="./file-icons/<name>.svg">` — relative because the packaged renderer is loaded from `file://`, and as a file because the full set is ~2 MB of path data (the whole JSON in the renderer bundle would cost every session). `lib/file-icons.ts` owns the lookup over the generated `lib/file-icons.map.json`: exact name (`Dockerfile`, `package.json`) → name glob × extension (`vite.config.ts`) → longest matching extension (`tar.gz` before `gz`) → generic file. That map is generated from **vscode-icons' own manifest** — the only place the associations exist — by `scripts/generate-file-icon-map.mjs` (`npm run icons:file-types`, needs network, commit its output including the recorded `source`); it resolves in this order: an explicit manifest entry is first-wins (vscode-icons' own generated manifest maps `ods` to `excel` and `otf` to `font`, i.e. the earlier entry), then `knownExtensions`/`knownFilenames` of the languages an entry declares (`knownFilenames` is where `Dockerfile`/`docker-compose.yml` live, so never drop it), whose contested keys are ranked by an id match on the key and then by the fewest claims (`html` over `django`, `postcss` over `css`, `reactjs` over `js` for `jsx`) — with `LANGUAGE_KEY_OVERRIDES` for the cases the ranking gets wrong on purpose (`.yml`). Verify with `node scripts/check-file-browser.mjs` (it asserts distinct icon sources for a Markdown/JSON/text/package.json set) and `node scripts/check-icons.mjs`.
- Markdown rendering exception: `react-markdown` in `lib/markdown.tsx` (a renderer, not a UI kit), with the remark plugins in [markdown-plugins.ts](src/renderer/src/lib/markdown-plugins.ts): `remark-gfm`, `remark-cjk-friendly` (CJK emphasis) and `remarkCjkAutolinkTrim` (literal autolinks glued to CJK punctuation). Code fences still render through beUI's `CodeBlock`; all other markdown elements are styled via the components map with beUI tokens.

- The interactive terminal uses `@xterm/xterm` as its screen/input engine (not a UI kit); all terminal chrome is composed from beUI Tabs and Button. `TerminalStore` owns emulator lifetimes outside pane mounts. Inner terminal tabs use beUI segments; top-level tabs keep their underline style. An exited terminal page shows only its status, with no restart button or residual screen; dispose its emulator/scrollback on exit and never recreate it when revisiting the page. The starting phase renders no status row at all — the surface attaches in well under a second, and a "Starting terminal…" line that flashes for a few frames reads as a glitch — while the exited/error message sits at the terminal's own body size (`TERMINAL_FONT_PX`, shared with the xterm `fontSize`), not the badge's 11px chrome. Output goes through `terminal:*` IPC, never Pi events or React state. `main/terminal/host.ts` is a separately built Electron utility process: it batches PTY output and pauses at a 128 Ki-character unacknowledged high watermark, resuming below 32 Ki after xterm's write callback. Preserve that end-to-end accounting, including while panes are hidden. `styles.css` also suppresses xterm 6's DOM scrollbar in the same global policy. `scripts/prepare-terminal.mjs` restores the macOS native spawn-helper's executable bit after install; electron-builder unpacks node-pty from asar. Terminal colors live in `styles.css` and are resolved/cached by `terminal-theme.ts`; keep ANSI black/white literal and keep the 256-color cube/RGB output untouched. `terminal-color-scheme.ts` adds mode 2031 notifications alongside xterm’s native OSC 10/11 queries. `TerminalFit` snapshots only a completed render during resize and removes its cover after the replacement frame, avoiding canvas-clear flashes without changing WebGL drawing-buffer behavior; never reintroduce `fit.fit()` on each drag frame. Verify with `node scripts/check-terminal.mjs` after building.

## Golden rule: every user-facing string goes through i18n

The UI ships in **English and 简体中文**; switching lives in Settings → Appearance and applies immediately. When adding or changing ANY user-visible renderer text (labels, placeholders, aria-labels, tooltips, empty/loading/error states):

1. Add the key to **both** `src/renderer/src/i18n/locales/en.ts` (source of truth) and `locales/zh-CN.ts` — the `Messages` type makes a missing/extra key a typecheck error. Keys are flat `domain.key` strings; use `{name}` placeholders for interpolation via `t(key, params)`.
2. Read strings with `const { t } = useI18n()` — never hard-code prose in JSX or template literals, including `aria-label`/`title` attributes.
3. Language names render via `LOCALE_NAMES` in their own language (never translated); add new locales by extending `Locale`, the `dictionaries` map and `LOCALE_NAMES` in `src/renderer/src/i18n/index.tsx`.
4. Known boundary: strings INSIDE vendored beUI components (e.g. ToolResult's "Completed", CodeBlock's "Ready") stay English — do not edit vendored files to translate them; pass app-level labels (`summary`, `activeLabel`, `title`, …) through `t()` instead.
5. The main process sends only data over IPC (no prose); compose any user-visible message from the rendered text in the renderer.

## Golden rule: scrollbars are invisible

**No scroll container ever shows scrollbar chrome.** Scrolling still works; the bar itself is hidden everywhere in the app. This is implemented once, app-wide, in `src/renderer/src/styles.css` (`scrollbar-width: none` on `*` plus `*::-webkit-scrollbar { display: none }`) — its single source of truth.

- Never style or re-enable scrollbars per element (no `::-webkit-scrollbar` rules, no width/thumb/track styling) and never edit a vendored beUI file to hide one. The `scrollbar-hide` utility stays only because vendored components still reference it; app code does not need it.
- Because the bar takes no layout space, a scroll container that holds focusable inputs needs its own padding (e.g. `p-1`) so focus rings are not clipped by the box edge.

## Continuous corners and elevation

- `styles.css` owns the entire corner scale: `--app-radius-detail` (4px), `inner` (10px), `item`/`control`/`icon` (14px), `card` (20px), `window` (28px). Both semantic Tailwind classes (`rounded-control`, `rounded-card`, etc.) and beUI's existing `rounded-sm` through `rounded-4xl` resolve to this scale. Use tokens in inline styles/animation targets too; no literal pixel radii or numeric `radius` props. `0` remains the intentional square edge.
- Native `corner-shape: var(--app-corner-shape)` defaults to `squircle` on every element and before/after pseudo-element, including portals. The base-layer rule gracefully falls back to circular arcs in unsupported engines. No SVG masks, extra observers or per-frame path generation.
- `rounded-full` explicitly means a true circle/capsule and sets `corner-shape: round`, including Tailwind pseudo-element variants. Both declarations are `!important`: Tailwind emits custom `@utility` rules before its own sorted radius scale, so a control carrying both `rounded-full` and a semantic radius (`size="icon"` adds `rounded-icon`) would otherwise win back a 14px radius and lose the circle. Reserve it for avatars, status/legend dots, loader artwork, ripples, deliberately circular icon controls and the explicitly named Tabs `pill` variant. **The selection controls are not in that list**: radios and their dot, checkboxes and every select-family trigger/panel are hard-edged (`rounded-control`/`rounded-item`), because the user asked for square selection controls on this branch — and the radio's and checkbox's marks are text-sized (14px box, `size-1.5` point / 9px check), not the vendored 20px ones, because the owner read the 20px marks as heavier than the line they mark. **Every on/off control is that checkbox** — the vendored `Switch` is no longer rendered anywhere ([checkbox.tsx](src/renderer/src/components/motion/checkbox.tsx) `mark="square"`). Ordinary text buttons/fields use `rounded-control`, and badges use `rounded-item`/`rounded-control`. For another intentionally circular geometry use `corner-round`. Layered surfaces use `rounded-inherit` to inherit **both** radius and shape.
- **Never add a circular `clip-path: inset(... round ...)` to a continuous surface.** It cuts off the squircle even at rest. CenterMorphModal and MorphPopover animate the native surface's uniform scale/opacity, keeping border, overflow clipping and shadow consistent throughout entry/exit. Reduced motion uses opacity only; `instant` previews keep their no-animation path. Popover's `PresenceGate` releases pointer/focus ownership at the start of exit.
- Select retains its edge-flattening motion using a unitless `--select-corner-progress` multiplier. CSS resolves the actual radius from the theme token on every frame; do not replace it with Motion-resolved fixed pixels. Tabs' moving indicator takes its radius from the same CSS classes as the tab, with no inline override.
- Floating surfaces use `shadow-overlay`, sourced from one light/dark elevation family. Keep real borders/focus rings separate; don't add an extra hairline to the shadow or a component-specific blur/drop-shadow. Nested diff/review bodies remain `rounded-none` under their single owning frame.
- `node scripts/check-corners.mjs` checks actual beUI controls in isolated Electron: continuous/circular geometry, pseudo-elements, inherited backgrounds, live token changes, per-frame native corner hit testing, markdown inline code's radius through the real transcript chain (bubble → streaming response → markdown), both themes, reduced/instant paths, focus trapping/restoration and exit cleanup. `PI_CORNERS_SCREENSHOT_DIR` optionally retains the gallery/dialog screenshots. Also run the written-file-preview and terminal checks after changing global geometry.

- Nested confirmation dialogs preserve their parent surface. Rewind keeps the checkpoint panel and diff DOM mounted while a sibling `CenterMorphModal` confirms single-file, batch, partial, Undo or Redo actions. Suspend the parent's interaction/focus trap, focus Cancel in the child, and return focus with `preventScroll` when cancelling; single-file preview loading must not remove the main diff. Both beUI modal families share `useModalScrollLock` so closing one layer does not unlock another, and unmounting all layers releases the lock. Portal child `MorphingModal` surfaces out of transformed/clipped parents (as in `CopyConfigDialog`).

Hard rules:

- Renderer **never** imports `electron` or pi packages; it talks only through `window.pi` (typed by `src/renderer/src/env.d.ts` referencing preload).
- New IPC surface = add DTO to `shared/types.ts` + handler in `main/ipc.ts` + method in `preload/index.ts`.
- Pi events flow: `PiManager` emits `pi:event` (serialized via JSON round-trip) → `PiStore.dispatch` → React. Render from `store.messages`; `store.streaming` is the live overlay. High-frequency deltas (`message_update`, `tool_execution_update`) are coalesced in `PiManager.emitEvent` (latest wins, ~33ms flush; ordered events flush first) — keep new hot-path events on that list.
- **The transcript keeps creation-time order, even for an event that arrives late.** The SDK's auto-retry strips the errored assistant round from the live agent state (`_prepareRetry`: "Remove error message from agent state (keep in session for history)"), so a snapshot rebuild has no slot for it and it re-enters `PiStore` later as a plain event. `PiStore.insertByTimestamp` gives it back its slot instead of appending it at the live edge — appending parked that round's error disclosure below the retry's rounds and made it drift as the run streamed. Equal timestamps keep arrival order; the optimistic user echo still compares against the transcript tail. Verify with `node scripts/check-transcript-order.mjs`.
- **`agent_settled` — not `agent_end` — means the run is over.** `agent_end` fires before post-run continuations (auto-retry, auto-compaction, queued messages), so clearing streaming/busy state or the sidebar spinner there lies while work continues. Only `agent_settled` (and `pi_error`) ends a run.
- **Managed bash process lifetimes are separate from SDK tool calls.** `main/bash/manager.ts` owns processes, bounded tails/logs and persisted task records; `main/pi/bash-tools.ts` registers app-owned `bash`/`bash_task` through `customTools`, overriding built-in/extension names while preserving SDK tool hooks and shell settings. `waitMs` is capped by the app's `bashMaxWaitMs` (default 10s); expiry yields the SAME process, while `timeout` kills its process tree. `agent_settled` only settles SDK calls, never background commands. Task metadata uses `pi:bash-task`, outside the sequenced transcript stream; output is read on demand. Renderer rows and folded group counts consult the independent task store. `SessionTasks` groups the Todo, Background tasks, Subagents and Q&A records entries above the transcript; exactly one panel is open, clicking the active entry closes it, and changing sessions resets its selection. Its expanded list floats over the transcript (an `absolute inset-x-0 top-full` wrapper with `rounded-b-card` + `shadow-overlay`), never in the flex flow: opening it must not push or scroll the page, and it owes an overlay's dismiss gestures (`useDismiss` for outside presses plus a capture-phase Escape that `preventDefault`s so it closes instead of stopping the run). It is full-bleed on purpose: the wrapper's box coincides with the chat column, so the panel's left/right edges ARE the column's two side lines (the sidebar's right rule and the rail's left rule) — it draws no side border of its own and squares every corner, because a border or a radius at that edge just doubles or dents the line already there. It draws no top border either: the strip's own bottom rule is the shared line, and only its bottom rule is its own. Nothing of it carries an elevation either: at full bleed any shadow spills a soft band past the very lines its box coincides with (the left one is clipped by the inset, the right one would smear the rail), so the drawer's own surface colour plus that bottom rule are what separate it from the transcript. Its own `AgentDisclosure` keeps its rectangular rest clip (`inset(0 0 0% 0)`) and the positioning wrapper clips nothing, so the reveal animation never cuts the drawer's own surface. Its list is capped at a whole number of collapsed rows — `max-h-[16.5rem]` = 4px edge padding + six 36px rows + five 8px gaps + 4px = 264px — and all four panels carry that same cap and rhythm (the todo list receives them through the vendored `viewportClassName`/`listClassName` patch), so a short list grows row by row while the four panels never exceed one height and the resting list still lands on a row boundary; the row a scroll actually cuts fades out through BeUI's capped-list mask (the same 12px ramp `AgentActivity` uses) instead of ending in a hard chop. Every row leads with the same `size-4` icon on the same 10px inset — the bash and subagent rows inset their `ToolResult` by 6px on top of the list's own 4px, exactly the todo row's 4 + 6 — so the four panels line up. Its four triggers are quiet toggles: their beUI press/hover scale is cancelled and the inactive variant carries a transparent 1px border, so pressing one neither pulses its label nor shoves its neighbours. Every new command must check the notification owner's `canStart` so stop/dispose cannot race another launch.
- **Rewind points exist only before user turns.** `main/rewind/recorder.ts` awaits the SDK user `message_start` barrier, then binds the checkpoint to the actual persisted message entry ID on `message_end`; timestamps and nearest-point guesses are insufficient. Never add tool-level, after-turn, resume or background-completion points. Capture's snapshot window is fenced only by work that can write the checkout — `tool`, `process` and `subagent` leases (extension-driven `executeBash` takes a `process` lease); another session's in-flight model turn (a plain `run` lease) must not starve pre-turn capture, and sibling tools queue behind an in-flight snapshot through `beforeToolCall`. File transactions remain durable independently of visible timepoints: `main/rewind/engine.ts` uses raw SHA-256 CAS, a fixed reviewed plan, before-image quarantine and verified journal phases, including index bytes and staged-only Git objects. Do not replace it with Git add/checkout/reset. `CheckoutCoordinator` owns admission across actual session/tool/process/terminal lifetimes; unresolved recovery must fence extension evaluation on startup. Conversation selection is persisted with an owned `pith_rewind_selection` entry and fsync before commitment; that entry also records whether the selected branch holds any message, because **the sidebar lists a session from its selected branch** — `SessionManager.listAll().messageCount` counts every branch in the file, so a restore to before the first turn used to keep a row whose chat could only open empty. `main/pi/session-branch.ts` reads the fact back from the file's tail (newest relevant entry: a message appended after the selection wins, the selection's recorded emptiness decides otherwise) instead of re-reading every session file, and a session with nothing on its branch leaves the list exactly like a never-used one; `onCommitted` re-reads the list so the row changes in the same interaction. Lost replies reconcile the journal before compensation. The latest checkout operation supports Undo/Redo, preserving unrelated paths. UI overwrite warnings conservatively cover every changed file/staging item because writer provenance is unknown; explicit force confirmation still requires a fresh preview and verified safety backup. It never bypasses active work, backup corruption or unresolved conflicts. Rewind and Review share `components/app/ReviewDiff.tsx` for headers, collapse controls and diff bodies; keep large rows windowed against the page, fetch only nearby preview bodies, and bound the IPC/cache. Settings text and all errors are bilingual. Details and limits: [docs/rewind-implementation.md](docs/rewind-implementation.md). Verify with `check-rewind.mjs`, `check-rewind-sdk.mjs`, `check-rewind-ui.mjs`, plus written-file-preview, terminal and task regressions when their shared paths change.
- **Rewind coverage is explicit.** `main/rewind/coverage.ts` diagnoses known successful `edit`/`write` paths from the complete selected SDK branch after the checkpoint. Missing originals outside the saved workspace or in exclusions require explicit partial-restore consent: list every skipped path, then restore only the immutable preview’s backed-up portion. The renderer sends only `skipUncovered`; main takes the omission list from the reviewed token, and the worker also checks consent. Never touch a skipped working path, ancestor or index entry; overlapping plans, stale previews, corruption and recovery fences remain hard errors. Persist skipped paths/reasons in the transaction, history and Undo/Redo previews, and distinguish partial success. Files-only with no restorable changes cannot report success; combined restore may explicitly leave files alone while restoring the conversation. Conversation-only and independently backed-up single-file actions do not grant partial batch consent. Never turn an empty standalone workspace backup into a claim that outside edits did not happen, infer shell writes from prose, or reconstruct missing originals from tool output. This diagnostic does not widen the pre-turn snapshot boundary. Keep change count, full-preview line totals, collapse-all, the split restore action and an icon-only backup information popover in one fixed toolbar row outside the diff scrollport, with no bottom bar; scrollport padding must not displace sticky Review file headers. Sidebars prioritize turn content over timestamp and backup count. History rows prioritize the file/scope and distinguish completed Restore, Undo and Redo from failure states. Previewable entries are whole beUI Buttons with selection keyed by preview.operationId; keep older entries passive and skipped-path disclosures outside those buttons. No separate sidebar preview buttons: row activation only previews, and the fixed toolbar executes. `RewindActions` composes beUI Button/MorphPopover: default to conversation-only; the dropdown only chooses a mode, and the primary action executes it. File-changing alternatives show overwrite/blocking warnings. Undo/Redo keep their saved mode. Nested popovers own Escape before the outer modal, restore focus, stay mutually exclusive and do not resize the toolbar. Restore mode controls execution, not preview visibility: all modes show the same file diffs, totals and collapse controls. Conversation-only copy must distinguish this reference preview from its conversation-only action. Uncovered paths warn before a partial restore without hiding independently backed-up file previews.
- **Single-file Rewind restores only the working file.** Derive its immutable child plan from the reviewed token; preserve raw Git staging and conversation, add only required missing parent directories, and reject ancestor-file replacement. Main and worker both enforce files mode. The normal journal, backup verification, overwrite warning and Undo/Redo remain mandatory; history carries the path. Staging and directory headers must not offer a misleading single-file action. Checkpoint headers opt out of path tooltips and fetch independent raw-blob numstat even when collapsed; do not count a truncated patch. Stats and bodies share three prioritized IPC slots: visible bodies, header stats, adjacent prefetch, then totals in batches of at most 16. Totals cover every worktree/index entry beyond pagination, exclude binary line counts, and never publish partial or stale results. Keep collapsed bodies in the bounded synchronous cache (64 entries / 8 MiB UTF-16 eviction budget, nearby active entries pinned), release offscreen parsed DOM, and recheck viewport geometry when queued fetches start. Layout changes must refresh both nearby visibility and virtual row windows before paint; a preceding collapse need not cause a resize/scroll event. Verify cache priority/admission/lifetimes with `check-rewind-preview-cache.mjs` and slow-IPC frame probes with `check-rewind-ui.mjs`. Keep the beUI modal context stable between confirmation and preview so focus returns to the triggering file action.

- **Todo state belongs to the complete selected branch.** `main/pi/todo-protocol.ts` parses only successful `todo_write` results and always returns sanitized data; legacy `pi-web-todo` details remain readable. `TodoState` in `main/pi/todo.ts` owns the per-session projection, restoring through `getBranch()` (never `session.messages` or `buildContextEntries`, which omit compacted tasks). The app registers `todo_write` as a custom tool plus a hidden inline context extension. Only committed `message_end` results update the projection; `execute` and `tool_result` are too early because other extensions can reject or transform them. Snapshots carry `todos`, and sequenced `agent_start`/result events carry changes into `PiStore`; compaction changes the transcript without clearing tasks. Explicit IDs survive renames/reordering; omitted IDs reuse matching tasks, and legacy identities are deterministic. Empty lists clear active state but retain the immediately preceding list (`retainedItems`) for UI review regardless of completion status; reconstruction derives it from the selected branch, reminders ignore it, and a new nonempty list replaces it. Retained rows preserve their original statuses under a localized history label, with no running animation even during a later turn. Cancelled tasks are not completed, and only new writes enforce at most one `in_progress`. Retries restore after both SDK navigation and the manual leaf rewind. Context reminders live only in the SDK's cloned request, handle custom completion/summary tails, and never send messages or wake an extra turn. Activity epochs prevent a same-batch todo from acknowledging unseen tool results. The beUI `TodoList` uses its minimal marked `headerless` patch under `SessionTasks`; idle progress is stationary without rewriting saved status. `node scripts/check-todos.mjs` covers the real SDK, persistence, branches, custom wakeups and snapshot races; `node scripts/check-bash-task-ui.mjs` covers the shared panels, geometry, keyboard/focus, locales, pause/clear behaviour and the panel's opening scroll target (centred running row, else the newest completed one).

- **Bash completion uses immediate steer, never follow-up.** `TaskNotifications` waits only for the original bash `toolResult` to enter history, then uses `sendCustomMessage(..., { deliverAs: 'steer', triggerTurn: true })`; the SDK consumes it at the next model/tool boundary or wakes an idle session. Its outbox acknowledges `message_end`, pins retained records, survives user queue rebuilding, and defers replay across the SDK's drain-before-message-start boundary to avoid duplicates. User prompt preflight blocks automatic idle wakeups until the SDK owns the run. Stop/Esc pauses notifications BEFORE recalling user queues, stops the session's commands, and prevents old completions from waking a resumed run. Delete, rewind and quit clean up process trees; ordinary chat switching and extension reload do not. Do not recover ownership from persisted PIDs. Completion custom messages remain tool passages in session search (`includeDetails`), not conversation prose. Verify with `node scripts/check-bash-tasks.mjs` and `node scripts/check-bash-task-ui.mjs`.

- **Subagents are real managed sessions with per-run persistence.** `src/main/pi/subagents/` owns the engine; the SDK has no native subagent support. The parent model calls the `agent` custom tool (registered per normal session, gated by the Settings toggle and the active-tool set in `initializeSession`); each run creates a full child `AgentSession` via `SessionManager.create(cwd, undefined, { parentSession })` through PiManager's own `createManagedSession` — one registry, one shutdown path, never an unmanaged session. ## DSH file sandbox, manual compaction and context menus

**The DSH file sandbox** (`src/main/sandbox/`) confines `bash`/`edit`/`write` to the workspace by default. Three modes — `read-only`, `workspace-write` (the default), `danger-full-access` — resolve through a runner chain in DSH order (seatbelt → bubblewrap → Landlock → Windows ACL → `dependencies-missing`); the optional native helpers are resolved through a **computed specifier** so another platform's bundle never tries to resolve them statically. Writable roots are the canonical workspace plus `/tmp` and `os.tmpdir()`; symlink-safe resolution walks the deepest existing ancestor. Bash is confined **before** a task record exists, so a confined mode with no usable runner can never become a "running" task that ran on the host. `edit`/`write` are app-owned tools over the SDK's `EditOperations`/`WriteOperations`, checked per side effect.

- **The mode is per session, not per app.** It is a custom branch entry (`pith_sandbox_mode`) folded with newest-wins; `AppSettings.sandboxMode` is only the default a new chat starts from. Tools read the live value, so a switch applies from the next tool call — including on a steered turn already running.
- **Escalation is one-shot.** `sandbox_permissions` + `justification` on `bash`/`edit`/`write`; a pending queue in main; published as a **sequence-free** `pi:event` metadata ping (the `context_usage` rule); answered from beUI's `ToolApproval` above the composer offering only "Allow once" — deliberately **no standing grant**, because a standing grant would outlive the question being answered. `check-file-browser.mjs` asserts its absence.
- **Deliberate deviations from pi-web** (recorded so they are not "fixed" later): pi-app keeps an app-level default for new chats; the broker owns no child processes (pi-app already has exactly one owner, `main/bash/manager.ts`, so the broker supplies only the confined argv, the scrubbed environment and the exit classification); the app sends data only and composes the escalation prose in the renderer; and escalation has no "always allow".
- Verify with `node scripts/check-sandbox.mjs` (real Seatbelt, no Electron, fast).

**ask_user_question is a native human-in-the-loop tool**, ported from pi-web's `lib/ask-user*.ts` onto this app's own escalation precedent (`src/main/sandbox/pending.ts`). [shared/ask-user.ts](src/shared/ask-user.ts) owns the protocol (1–4 questions per call, 2–4 options each, optional multiSelect, free-text answer always allowed, `details.kind = 'pi-app-ask-user'`) plus every defensive normalizer; [main/pi/ask-user.ts](src/main/pi/ask-user.ts) owns the pending registry and the customTool registered in `buildSession` beside `todo_write`. Claude Code semantics: the question waits for the user while they are working on it; skip/Esc is an explicit cancel whose result text tells the model to continue on stated assumptions, never an error; every teardown path (abort signal, dispose, child-run teardown) settles as cancelled so the agent loop never hangs. **Two modes**, chosen by the model: `blocking` (the default — the call waits) and `async`, the background-command shape — the call returns a receipt at once (`status: 'pending'`), the model keeps working, and the outcome is steered in later by [ask-user-notifications.ts](src/main/pi/ask-user-notifications.ts). An async question therefore does NOT take its call's abort signal (the call is over; the user can still answer), and its outcome arrives as an `ask_user_answer` custom message rendered through the same `AskUserResultCard` and folded as a notice beside `bash_task_completion`. That outbox keeps the other two completions' rules: a delivery waits until the receipt's toolResult is in the branch (`receiptPresent` — which is also why a rewind drops it at the next settled boundary instead of injecting an answer into a branch that no longer asked), the send is acknowledged by the SDK *consuming* it rather than by the promise resolving, and `queueCleared`/`pause`/`resume`/`holdWake`/`flush` are wired wherever the bash and subagent owners are. **Only a real answer repays `triggerTurn`**: a timeout is appended quietly while the session is idle, because the user walked away and the model's own turn already moved on — while everything steers into a live turn.

**Auto-settle is an engagement deadline, not a stopwatch.** `Settings → General → askUserTimeoutSeconds` (default 120s, 10–3600) arms a timer in `waitForAskUser`; the user's FIRST real interaction cancels it for good and publishes `engaged` through the ordinary republish (main owns the clock — the panel only reads the remaining time down in the kicker row), and collapsing deliberately does not report, because folding the question away parks it rather than engaging it. The timeout settles as `cancelled` with `reason: 'timeout'`, whose result text and card badge say the user never answered instead of pretending they dismissed it, and an interrupted run reads `aborted` — the three reasons are separate because the model is told to behave differently.

## Shell layout: three columns, one budget

The native frame uses `main/window-chrome.ts` (`titleBarStyle: 'hidden'`, native traffic lights/controls overlay). `WindowTitlebar.tsx` owns the renderer row shared by Workspace, Settings and startup; `styles.css` owns its 52px height and platform control insets. Keep the native overlay height/traffic-light position aligned with that row. The three workspace columns are siblings in the flex row **below** it, so the left navigation and right tools share the full remaining height. Never reintroduce a second conversation header for model information (the composer already owns the model picker). Title-row buttons and the project-path tooltip opt out of native dragging. Visible modal dialogs disable title dragging; hidden mobile dialogs must not. The mobile sidebar reserves the title-row height so its first action clears native controls. Theme changes use the typed `window:setTheme` bridge; renderer code never imports Electron. **The title row has one pocket for later actions** (`TitlebarOverflow.tsx`): the four original controls keep their places, and everything added after them lives behind a single chevron that LEADS the row's right-hand action group, collapsed by default, unfolding LEFTWARD into the title's space on click so neither the chevron nor the controls beside it ever move. Collapsed, the pocket is unmounted — a control at zero width must not stay tabbable — so only the buttons inside `actions` are its own; Escape closes it (synthesizing the event, the flag the composer's Esc-to-stop reads) and returns focus to the chevron. Today it holds the two SDK command-palette actions, in the palette's own order: `/compact` (`pi:compact` → `PiManager.compactSession`, the manual `AgentSession.compact()`) and `/reload` (`pi:reload` → `PiManager.reloadSession`, which re-reads extensions, skills, prompts and context files for every live session). Both are refused while the session runs — the SDK's manual compaction aborts the live turn and never retries it, and a reload would swap the extension runner under the request in flight — so the user stops the turn first, and the palette and the pocket share one handler per action (`handleCompact`/`handleReload`) rather than drifting apart. `node scripts/check-window-chrome.mjs` exercises the built renderer in an isolated profile with synthetic sessions (it pins the pocket's rest/reveal geometry, the immobility of the controls beside it and its Escape ownership and round trip to main); `PI_WINDOW_SCREENSHOT_DIR` retains screenshots.

`src/renderer/src/lib/panel-layout.ts` owns the numbers (min/max per panel, `CHAT_MIN` for the transcript, `fitPanelLayout`, `clampPanelWidth`, localStorage persistence). The workspace keeps the widths the user **set** (`panelPreference`) apart from what is **on screen** (`fitPanelLayout(preference, viewportWidth, visibility)`), so a narrow window shrinks the panels without ratcheting the preference down — widening it again brings back what the user chose. Dragging is `PanelResizeHandle` + `useDragResize`, which listens on `window` rather than using `setPointerCapture` (a 6px strip is left immediately, and capture is not honoured by every input path). The strip sits *outside* the panel as a flex sibling: the sidebar's own panel clips its content (which is exactly why the vendored rail only had a 2px hit area), and a press that never dragged toggles the panel, replacing that rail. The right rail folds itself when its last tab closes; the transcript's changed-files `Review` action opens it and selects the turn.

Three things there are load-bearing for a resize that does not stutter (a long session is ~20k elements, and a naive drag measured 40 dropped frames per gesture):

- **A drag renders nothing.** `resizePanels` writes the pair to the two panels as CSS variables directly (no React state), so only the panels and the transcript reflow; the width is committed to `panelPreference` on release, when the drag is over. **Both** panels read those variables for as long as *either* strip is pulled (`resizing !== null`): a left-panel drag shrinks the rail in the same frame, and only the panel that is actually being dragged may follow the pointer. The dragged panel's ceiling is `clampPanelWidth(…, siblingMin, viewport)`, so the pair can never reserve less than the sibling's floor plus `CHAT_MIN` — the transcript is the one column a drag may not squeeze, and a drag that would is simply capped.
- **The two top rules are one line.** The transcript's task strip and the rail's tab strip are both “a 44px control row + 1px rule” (the tab strip must stay content-driven: `h-11` would make its rule 1px higher, since a fixed height is border-box), and the right resize strip straddles *both* columns (`-mx-[3px]`, i.e. no layout width) rather than only the rail (`-mr-[3px]`), which is what puts the boundary — and therefore the task strip's right end — exactly on the rail's left border instead of three pixels short of it. The left strip keeps `-ml-[3px]`, compensated by `AnimatedSidebarInset`'s own `-ml-[3px]`.
- **Each write goes to that panel's own element**, never to a shared ancestor: a custom property is *inherited*, so writing it higher up invalidates the computed style of everything below (~25k elements per pointermove — 0.8s of style recalc for one drag).
- **The transcript skips offscreen turns** (`content-visibility: auto` on `[data-slot="message-group"] > *`, in `styles.css`). Without it, re-wrapping every turn per frame is the whole cost; with it, layout during a drag is ~0. It is deliberately always on: toggling it for the gesture made the browser lay out every skipped row at once on release — a ~120ms freeze at the end of each drag. The drag overlay (`fixed inset-0`, while a gesture runs) exists for the same reason: the obvious `body[data-panel-resizing]` cursor/user-select rule invalidated the whole document's style at both ends of the drag.

## Pi SDK facts (learned from the installed package, 0.85.x)

- Read types from `node_modules/@earendil-works/pi-coding-agent/dist/**/*.d.ts`; `pi-ai`/`pi-agent-core` are **nested** under it (`.../pi-coding-agent/node_modules/@earendil-works/`).
- `ImageContent` is `{ type: "image", data: base64, mimeType }` — the online SDK docs show an older `source`-based shape; trust the installed `.d.ts`.
- Assistant messages have no id — key rows by `role+timestamp+index`.
- Tools used: the seven built-ins `read`, `bash`, `edit`, `write`, `grep`, `find`, `ls` (set explicitly, see the allowlist note above) plus every tool an enabled extension registers (`web_search`/`web_fetch` from Tavily, `mcp`/`mcpScript`/`mcp__context7` from the MCP adapter, `ffgrep`/`fffind`/`fff-multi-grep` from pi-fff, the `ctx_*` family from context-mode). `edit` returns a unified diff in `details.patch` (parsed in `lib/diff.ts` → beUI `FileDiff` lines); `write` returns no details, so the app synthesizes its diff from the call's `content`.
- Credentials are shared with the `pi` CLI via `~/.pi/agent/auth.json`.
- **Context files (AGENTS.md/CLAUDE.md) are injected as a `<project_context>` block**; discovery loads the global agent dir plus every ancestor directory down to `cwd` (first candidate per dir: `AGENTS.override.md` → `AGENTS.md` → `AGENTS.MD` → `CLAUDE.md` → `CLAUDE.MD`). `noContextFiles` is fixed at loader construction, so the app instead passes an `agentsFilesOverride` that reads `PiManager.includeContextFiles` **live** — `session.reload()` re-runs it, which is what makes Settings → Prompt → Context files apply to live sessions.
- **Global append prompt lives at `~/.pi/agent/APPEND_SYSTEM.md`** (the project-local `.pi/APPEND_SYSTEM.md` is its trusted-project counterpart). `DefaultResourceLoader` reads it at load/reload time, and each session caches the built base system prompt, so editing the file does **not** reach a live session until `AgentSession.reload()` — `PiManager.setAppendPrompt` reloads idle sessions and defers streaming ones to `agent_settled`.
- **Resend/retry = `navigateTree(userEntryId)` + re-`prompt`** (same file; the abandoned branch stays in the session tree). Targeting a user message drops it and everything after, and returns its text as `editorText`. It THROWS while streaming, and **emits no AgentSession event** — `PiManager.resendMessage` bumps `managed.eventSequence` by hand so the returned snapshot isn't mistaken for one the renderer already has. When the user message is already the leaf (a run that died before any assistant output) `navigateTree` no-ops — rewind via `sessionManager.branch(parentId)` / `resetLeaf()` + `agent.state.messages = buildSessionContext().messages` like it does internally.
- **Fork at a message = `SessionManager.open(sourceFile).createBranchedSession(entryId)`** on a separate manager. The SDK mutates the receiver's file/id/branch; never call it on the live source manager. Otherwise the source writes into the fork, and deleting that fork followed by continuing the source recreates a headerless file. The fork ends at the selected entry with `parentSession` pointing back; `scripts/check-session-persistence.mjs` covers independent writes and delete-fork/continue-source. Renderer messages are correlated to entries by `role+timestamp` over `buildContextEntries()` (`findMessageEntry`).

## Gotchas

- **Dependency versions are pinned by peer conflicts**: electron-vite 5 supports only vite ^5–7 (NOT vite 8); `@vitejs/plugin-react` must be ^5.2 for vite 7. Don't blindly upgrade.
- **Main entry must build to `out/main/index.mjs`**: electron-vite's lib-mode default emits `.js`. The explicit `rollupOptions.input` + `output: { format: 'es', entryFileNames: '[name].mjs' }` in `electron.vite.config.ts` is load-bearing — keep it.
- If `npm run preview` says "Electron uninstall", run `node node_modules/electron/install.js` (postinstall can be skipped).
- Running `electron out/main/index.mjs` directly uses `~/Library/Application Support/Electron` as userData instead of `pi-app` — prefer `npm run preview`. Settings live at `<userData>/app-settings.json` (`{ cwd, folders }`).
- E2E/smoke testing without screen access: launch with `--remote-debugging-port=9222`, then a small Node script over the CDP WebSocket (`Runtime.evaluate`, `Page.captureScreenshot`) — real model calls cost fractions of a cent on locally configured providers.
- beUI components rely on `@/` → `src/renderer/src` alias and on `dark:` = `.dark` class (next-themes); accents are `[data-accent=…]` presets in `styles.css`.
- Vendored beUI edits must stay marked `// local patch (pi-app)` and minimal (see above) — they are the one exception to "treat beUI as vendored".
- All process code is ESM (`"type": "module"`); preload requires `sandbox: false` in the BrowserWindow.
