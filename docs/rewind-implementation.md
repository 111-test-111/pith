# Rewind：移植、正确性边界与验收

本次从 `native-subagents` 移植检查点、预览、文件/会话/组合恢复、恢复历史及设置，并重写文件事务内核。按后续产品要求，常规面板**只提供每轮用户消息开始前的时间点**；工具调用后、会话打开和后台命令结束均不新增点。时间点粒度的简化不取消内部安全备份。

## 用户行为

- 会话标题栏、会话菜单和用户消息行提供入口。消息行用真实 SDK entry ID 选择对应轮前点；没有对应备份时明确显示不可用，不猜测最近时间戳。
- Settings → General 的自动检查点默认开启；关闭后立即停止新增，已有轮前点和恢复历史保留。每个会话最多 50 个检查点。
- 文件头、增删颜色、行号、diff 正文和全部折叠/展开与 Review 共用 `ReviewDiff.tsx`，均由现有 beUI 组件组成。工作区与暂存区分开显示，冲突 index 的 stage 1/2/3 分别显示。大 diff 按可视行渲染，正文只在文件接近视口时请求。
- 改动数、总增删、全部折叠/展开、还原操作和信息按钮位于独立于 diff 滚动区域的单行顶部栏；没有底栏。三个模式单选按钮合成一个拆分按钮，默认仅还原会话，下拉只选择其他模式，主按钮才执行。文件模式涉及覆盖或存在恢复阻塞时，选项显示警告图标；仍保留执行前的明确覆盖确认。Undo/Redo 固定原操作模式。总增删包含完整预览的工作区与暂存区条目（包括尚未翻页的文件），按恢复方向计数，二进制另计，统计失败可重试，不用部分结果冒充总数。文件头吸附在正文滚动区域顶边。侧栏优先显示轮次内容，时间和已备份文件数为次要信息，选中项有底色与勾选标记；窄窗口使用简短但仍带还原动词的按钮文案，所有操作仍保持一行。还原模式只决定执行范围：默认仅会话时也显示同一份文件 diff、总增删、折叠和逐文件回退入口，文案明确这些差异供核对，主按钮仍只还原会话。切换模式不卸载正文、重算统计或清空折叠状态；个别未覆盖路径的警告不隐藏已备份文件的差异。
- 操作历史采用紧凑列表，优先显示文件名或还原范围，其次是已还原、已撤销、已重做或未完成状态，时间为次要信息。可撤销/重做的条目整行使用 beUI Button，点击或键盘激活直接进入对应预览，不执行恢复；侧栏不再显示独立预览按钮。选中态绑定预览的 operation ID，实际执行保留在顶部栏。旧记录保持可读但不伪装成可预览项，已跳过路径使用独立的明细展开控件，不嵌套在条目按钮内。
- 移除“备份范围与排除项”文字入口，改用顶部栏右端的信息按钮；点击打开 beUI 浮窗，内容限制高度并独立滚动，不挤动 diff。信息与模式浮窗互斥，Escape 先关闭浮窗并返回触发按钮；模式选项支持方向键与 Enter。能力说明和阈值是当前实现的固定规则；具体路径合并所选检查点与当前预览的排除记录，会因仓库、ignore 配置、文件大小/类型及子模块而变化。
- 检查点文件头禁用路径 tooltip。增删数量由保存的原始字节执行独立 `git diff --numstat` 得到，接近视口时即加载，折叠时保留；不需要下载/展开 diff 正文，也不从可能截断的正文计数。文本的零增删明确显示 `+0 / −0`，二进制另作标记，加载或失败时不伪造数字。
- 工作区文件头右侧提供单文件回退，目标是所选轮次开始前的文件内容、类型和权限（也包括恢复文件不存在的状态）。确认框显示路径，并明确保留 Git 暂存区及会话；暂存区行和目录行没有这个按钮。子计划只从已审阅的不可变预览提取该文件，必要时创建缺失父目录，拒绝替换挡路的父文件。主进程和内核均强制仅文件模式，沿用安全备份、覆盖确认、执行前复核、事务恢复、幂等及跨重启 Undo/Redo。成功后刷新剩余差异，操作历史记录对应路径。
- 选择时间点后，diff 的方向为“当前状态 → 保存状态”。文件恢复将替换已存在改动时，弹窗警告，默认焦点是取消，用户可选择**备份并强制回退**。文件系统不能可靠归因到某个作者，因此对所有将被替换的改动保守警告，包含其他会话、编辑器和本会话自身的改动。
- 单文件、整体、部分还原及 Undo/Redo 的确认框叠在检查点面板之上，保留下面的 diff、滚动位置和折叠状态。子框打开时，父面板保持显示但暂停交互，只有子框接管键盘焦点；取消、Escape、关闭按钮或点击背景只关闭子框，并将焦点返回原操作按钮。异步请求单文件预览也不卸载现有 diff。两层弹窗共享滚动锁，避免关闭子层时解锁页面或同时关闭后残留锁定。
- 强制回退仍遵守已审阅的预览和备份流程。若磁盘或会话在预览后又变化，操作停止；通过“刷新差异后再强制回退”生成新预览，再次确认。强制操作不绕过损坏检查、活动命令、排除路径或未解决事务。
- 仅会话恢复选中完整 SDK 分支并恢复 Todo/ChangeScopes；文件模式恢复原始文件与 Git 暂存区。组合模式由 main 协调两阶段，失败时补偿回到操作前状态。HEAD 不移动。
- 当前 checkout 最近一次成功操作可 Undo，Undo 后可 Redo，跨重启有效；这不是任意深度的撤销栈。Undo 只反转原操作涉及的路径，无关的后来新增文件保留；同路径的后来修改会进入新预览和覆盖警告。
- 检查点失败会显示标题栏警告和面板错误，不伪造备份成功。已有恢复事务未解决时，面板显示恢复入口和保存冲突内容的路径，启动命令和外部扩展受到阻止。
- 独立会话仍有自己的工作目录，轮前备份不会自动扩大到工具随后访问的其他目录。预览会从完整选中分支的成功 `edit`/`write` 记录检查已知路径：位于工作目录外或明确排除范围内的改动会列出警告。缺少原件时，可在确认框逐项核对跳过路径，明确确认后批量恢复预览中已有备份的部分；跳过文件保持现状。主进程从预览 token 取出跳过清单，渲染器只发送确认标志，worker 再次检查。若操作会触及跳过的工作路径、父路径或暂存区条目，仍拒绝执行。成功提示与操作历史明确标注部分恢复，并持久保存跳过路径和原因；重启后的 Undo/Redo 继承同一清单且再次要求确认，不能扩大恢复范围。仅文件模式没有可恢复改动时禁用；组合模式可明确跳过所有未备份文件而只恢复会话。仅会话和独立单文件操作无需授权跳过整批文件。空备份不会把已知目录外改动表示成“没有改动”，既有备份也不能追补过去未保存的原始字节。

## 正确性设计

1. **原始字节备份。** SHA-256 内容寻址存储独立于 Git 的 clean/smudge、autocrlf 和 `git add`。工作文件、原始符号链接目标、POSIX mode、raw index、split-index 依赖和 staged-only Git blob 分开保存；assume-unchanged/skip-worktree 不使已跟踪文件漏备份。
2. **轮前屏障。** SDK awaited `message_start` 先完成文件采集，之后才继续本轮。用户消息提交后，再把该点绑定到实际 entry ID。同毫秒、相同文本不会合并为一个点。记录检查点不向会话追加隐藏消息。
3. **不可变计划。** 预览 token 绑定会话、目标和磁盘快照，15 分钟有效；执行时复核根目录/Git 目录/index 路径、分支、文件内容及会话叶子。计划外的新文件从不临时加入删除集合。
4. **先持久化再改文件。** 校验所有受影响内容，刷盘备份及目录项，写入带校验和的 recovery marker 和 journal，然后隔离原文件。输出通过 no-replace 发布；目录仅在为空时移除，不使用递归删除或 `git reset --hard`。
5. **可恢复的隔离区。** 被替换的原文件移入同文件系统的事务目录，写入前后逐项核对。发现竞态保留当前文件和被移走的原件，不把未经验证的结果报告为成功。重复恢复继续使用同一事务，无法解决的冲突仍保留。
6. **Git index 单独处理。** 持有可证明归属的 index.lock，恢复 raw index，补齐可能被 Git GC 收走的 staged-only 对象。工作文件内容不从 Git normalized blob 重建。
7. **会话选择也必须落盘。** SDK `branch`/`resetLeaf` 本身只改内存；追加最小 `pith_rewind_selection` entry 并 fsync 后才提交组合事务。若提交响应丢失，先读取持久化事务结果，不能只把会话回滚造成文件/会话分裂。
8. **启动恢复优先于扩展加载。** main 先读取小型恢复标记；待恢复 checkout 只打开 transcript，不执行外部扩展工厂。恢复完成才重建该会话自己的正常 loader。活动 SDK 轮次、工具、后台进程生命周期和交互终端均受 main 协调；终端宿主异常丢失时阻止本次应用生命周期内的恢复，并提示核实命令后重启。

## 保障范围与限制

这是经过故障注入验证的实现，不是形式化证明或“任何情况下绝不丢数据”的承诺。当前实测平台是本机 macOS 的本地文件系统与 Git；Windows/Linux、网络文件系统、设备断电及硬件损坏没有做同等环境验收。

- 不包括编辑器尚未保存的缓冲区、外部服务/数据库、文件所有权、ACL、扩展属性、文件时间戳以及任意工作目录外的副作用。
- 未覆盖路径诊断以已提交、成功的内置 `edit`/`write` 工具记录为依据，按当前文件系统解析符号链接及已删除文件的父路径；它不是全系统写入审计，不能穷举任意 bash、扩展、其他会话或外部程序的副作用，也不从工具正文猜测或重建原件。
- Git ignore、约定的依赖/构建目录、超过 10 MiB 的未跟踪文件、同非根目录下至少 200 个未跟踪文件、子模块内容、硬链接和特殊文件属于显式排除范围。已跟踪的普通文件不因 untracked 大小阈值漏掉。路径/排除范围会进入预览，发生危险相交时拒绝。
- 源版本的 Git refs 仍可由兼容内核只读解析并按需导入；不会删除或重写 refs。它不能还原当初 Git filters 已丢弃的原始字节，也不能伪造缺失的会话锚点。旧版工具后/打开时的快照不冒充轮前点，常规面板只显示新的准确轮前记录。
- app 内协调不等于跨所有进程的文件系统事务锁。独立编辑器、CLI、其他 app 实例、逃逸到其他目录的命令仍可能写入。文件逐个替换，外部观察者可能看到中间状态。预检、隔离和 no-replace 降低并检测竞态；持续恶意写入或目录在系统调用之间被替换，无法由可移植 Node API 提供全局原子性。
- “强制”明确允许覆盖审阅到的当前改动，但不允许在持续竞态中盲写。无法确认一致性时继续显示冲突/恢复要求，保留救援内容。

## 存储与性能

存储位于 `<userData>/rewind`。文件和 Git I/O、散列与 diff 在独立 worker 内执行；stat 身份缓存复用未变字节，CAS 去重避免重复写入，小对象并发写入受限，目录 fsync 在发布 manifest 前批量完成。保护路径用按段索引，避免“排除路径数 × 跟踪文件数”的交叉扫描。列表读取小型派生头记录。

统计和正文 IPC 共用最多 3 个并发槽，可见正文优先，其次文件头统计、相邻正文预取，最后是总数统计。总数每批最多 16 条，worker 内最多并行 4 个 numstat；批间归还调度权，不一次占用 worker 处理整仓库。统计缓存最多 2,000 条小型数字记录。单份 patch 输出约 2 MiB 上限，正文缓存以 64 份/约 8 MiB UTF-16 文本为淘汰预算，附近正在使用的正文暂时固定，离开后重新淘汰；缓存与解析行没有每文件的隐性副本。

正文在视口上下 1,200px 内准备，并预取接近视口文件之后的两份原始 patch；远处不解析/挂载正文，首次列出 100 个文件，继续显示按 100 个递增。队列实际执行前重查位置，跳过“全部展开”后已被上方正文推远的文件；可见请求可以接管之前的预取。折叠保留有界缓存，再展开同步读取，不先绘制加载提示。折叠导致下方文件位置变化时，在浏览器绘制前同步更新可见状态及大 diff 的行窗口，避免沿用旧窗口出现空白。超过 400 行的 diff 使用 Review 共用的页面行窗口，不增加每文件纵向滚动条，不对大文件运行语法高亮。

每会话 50 个检查点；每 checkout 保留最近 100 个完整终态事务，更早结果压缩为绑定 token 的幂等记录。未完成事务始终保留。预览最多 24 个，15 分钟过期；维护删除超过 24 小时且不再被任何保留记录引用的 CAS 对象。删除会话时备份不随会话立即销毁，以保留 OS Trash 恢复后的可用性；备份目录不是加密保险库，也不是无限期全盘备份。

一万文件、10 个检查点的隔离语料实测，原始及最终 JSON 位于本目录的 `rewind-performance-*.json`。优化前首次检查点约 154 秒、单文件恢复约 51 秒；优化后约 37 秒与 2.2 秒。热检查点约 0.71 秒、列表约 27 ms、单文件预览约 0.75 秒、正文约 66 ms。新建无内存 stat 缓存的引擎后，列表约 51 ms、预览约 2.0 秒、正文约 65 ms（操作系统文件缓存仍然是热的）。首次全量备份仍有明显成本；这些是该语料本机测量，不是任意项目的延迟保证。

单文件功能补测使用独立的 1,000 文件/10 检查点语料（`rewind-performance-file-restore.json`）：完整预览约 231 ms，独立增删统计约 57 ms，单文件子预览约 66 ms，事务恢复约 550 ms；无内存缓存的新引擎完整预览约 606 ms。语料规模与上述一万文件结果不同，不能直接比较。

隔离 Electron 的 1,000 文件/6,000 行 UI 语料，新增总数与单行工具栏后首个 diff 约 150 ms，挂载 52 行。另以 40 文件/每份 6,000 行、每次正文 IPC 延迟 90 ms 的语料，首个可见 diff 约 192 ms，缓存后的全部展开首帧约 38 ms；逐帧检查折叠、全部展开、相邻滚动和下方已挂载文件的位置变化，未出现可见加载提示或空白行窗口。这仅测本机界面呈现和模拟 IPC，不能替代真实文件系统测量或保证任意滚动速度下的延迟。

## 验证
