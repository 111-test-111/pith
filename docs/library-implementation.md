# Library

The Library page collects conversation resources across projects. Open it from the sessions sidebar or titlebar overflow; Settings → Library controls collection, the archive directory and the copy quota. Images use the vendored beUI Infinite Masonry, bounded pagination and the shared image preview. Files and JSON web source records open through the existing read-only file panes. Every record retains its originating session and entry, project, source and time.

## Collection

`main/library/` owns extraction, archive storage, the worker and IPC. Shared DTOs live in `shared/library.ts`; preferences belong to `AppSettings.library`. Renderer operations use the typed preload API. No base64 image data or file bodies appear in library change broadcasts.

Files come from user attachment blocks, matching successful `present` call/results and validated committed `image` receipts. Image batches retain earlier committed files even if a later save fails. The collector also accepts user image blocks, returned generated images and browser screenshots, search/fetch sources, and parsed web links in replies. Arbitrary tool-result file paths, local Markdown links (including relative repository links in fetched pages), source citations with line numbers, ordinary reads and edits are excluded. Remote image references retain their URL rather than issuing a new download.

Original file names are retained for path attachments, deliveries and generated images with committed paths. The latter archive the original file, including SVG, rather than its raster preview. SDK inline image blocks often contain bytes and MIME type without a filename; these display a localized source label and their conversation title. Multiple images are numbered within the image list rather than by their text/image block position. Ordinary image reads do not create extra library records. Collection-version upgrades remove obsolete local reference/read records and inferred download files/images, release only unreferenced managed copies and invalidate history fingerprints to refresh image labels. User removal tombstones and generated-image identities survive upgrades.

PiManager submits committed user/tool messages, records nested tool results while their actual bodies remain available, and signals appended session files. Browser downloads record their source URL in Web on successful completion and freeze their session/project provenance at download start. They do not create local file/image records; a downloaded file must subsequently be attached or presented to enter Files or Images. The collector does not infer arbitrary shell writes or scan a project's entire filesystem.

The worker incrementally scans the SDK session directory at startup and periodically. Fingerprints, verified append tails and bounded persisted call parameters avoid repeatedly parsing unchanged history. All branches, child sessions and scheduled sessions can contribute resources. Projectless resources are grouped separately; the internal workspace is never a project label. Library retention is independent of session deletion, compaction and Rewind. A removed library record has a durable tombstone, so a later rescan cannot reintroduce it.

History scans yield between message batches to prioritize live captures. Page/status requests read committed index rows while background copies proceed; opening or filtering the library never triggers a scan. Explicit recollection also retries failed attachment/delivery copies and copies that previously exceeded quota. Historical nested records retain arguments/status but omit result bodies; missing historical images, search output or original files cannot be reconstructed from those parameters.

## Gallery and filters

The shared enlarged image viewer navigates the current image filters with Left/Right arrows or its previous/next controls. Its collection comes from indexed saved image records, including virtualized offscreen cards, rather than mounted image elements. At a page boundary it requests the next existing Library cursor and advances after that page arrives; unavailable records contribute no preview and navigation stops at the final filtered result. Filter/category changes release the preceding collection, and closing a viewer prevents an outstanding page request from selecting an image in a subsequent viewer.

Image dimensions are persisted before a record is published: validated inline images use the decoder's original dimensions, while local copies use bounded header inspection. Startup backfills dimensions from retained objects without needing their originating sessions. Unknown formats retain a fixed fallback frame. Image cards show only the picture, at its reserved aspect ratio, using the same window-radius token as the enlarged viewer. Exact sizes go to the virtualizer rather than being measured after decoding. Mounted virtual cards load eagerly; virtualization bounds their number. Late decoding and failure placeholders therefore cannot rewrite masonry lanes or the scroll offset. Pagination appends real cards without transient skeleton rows changing an existing gallery's scroll range. Width changes reflow existing items without remounting or refetching data.

A transparent image canvas uses a faint theme-colored alpha grid to distinguish white or transparent image edges. The image gallery uses 24px gaps in both directions. A selected image gets a thin accent ring without affecting geometry. Selection paints immediately, while pointer single-click information waits 200 ms; a quick double-click cancels that pending action before opening the shared enlarged viewer. A later native second press also dismisses already-open information, preserving the original card as its click target. Keyboard activation opens information immediately. Dismissal, scrolling, filtering and page teardown cancel pending clicks.

Files use a virtualized three-line list: original filename; project and source conversation; delivery/attachment, size and date. File artwork aligns with the filename rather than the whole row. Listing and paging read metadata only. Selecting a row opens the retained copy beside the list through `FilePreviewPane`, the same full readers and controls used by the conversation's file rail. Library owns a separate `FileBrowserStore` and never opens or changes the conversation for file selection. Source/preview, PDF page and zoom controls, tables, confined HTML, media, fonts, search, copy and export remain available. Markdown initially selects literal source; all text starts with wrapping enabled. A resizable split keeps the list visible, and width changes neither remount the reader nor re-query the index. Archive refresh or directory migration rebinds an already-open preview to the updated retained copy. Stale asynchronous selections cannot replace a newer selection; unavailable rows show information without retaining the previous file canvas.

Web uses that same single-column list and split preview component. Its three lines show the title with a Web glyph; URL or query; source, project, size and date. Click or Enter selects a retained JSON record in the adjacent file pane, initially on Preview, with Source available. The list remains visible and uses the same bounded cursor paging and resize behavior. Information retains the URL, query, excerpt and originating conversation; the shared toolbar provides source-website opening, Info, full-document Save As, source conversation, removal and closing. Switching between Files and Web starts a distinct selection/reader owner, so one category cannot display the other's rows or preview. View filtering and confirmed clearing use the normal Library scope rules.

Images use one beUI information popover beside the selected card. It contains the name, conversation, dimensions, project/date, source/storage/size and preview, Save As, source-conversation and removal actions. It flips sides and clamps to the viewport, portals outside the scrollport, and closes on dismissal, scrolling or filtering. Keyboard activation focuses the information panel; Escape returns to the card before leaving Library. Files place their metadata in a beUI information popover opened by the Info button in the preview toolbar. Refresh, OS opening, folder reveal, one full-byte Save As action, information, source conversation, removal and preview closing share that single toolbar; viewer-specific navigation stays with its engine. Opening information does not remount or read the file again. Removal keeps its parent mounted and inert while the confirmation owns focus, then restores the action on cancellation.

Each page has a Clear action with a second confirmation. It removes the entire current category across every project, including records hidden by availability, search or project filters; the dialog states that scope explicitly. The worker validates the category and commits all deletion tombstones in one indexed update, then releases only objects without a live reference. Shared copies in other categories survive; originals and conversations remain untouched. Confirmation focuses Cancel, blocks repeated submissions while running, and handles Escape/cancellation without changing the library. Later history scans and restarts cannot restore cleared records.

Images, Files and Web use underline tabs with centered category icons and labels. The project picker displays only the project basename on one line. Longer names borrow space from the search input; identity and grouping still use the full project path. Hide unavailable content is enabled by default and remembered as renderer view state. The index applies it before counts and cursor pagination: local records need a retained copy, while Web records remain usable with a valid source URL or saved JSON record, including a query without returned text. The filter uses known archive availability and does not probe remote sites. Losing an original file never hides an intact retained copy.

The renderer retains one metadata snapshot per category, bound to its project, search and availability filters. Switching tabs selects the corresponding snapshot in the same render; rows and counts cannot leak from the previous category. Known content, including a known empty result, stays visible during background index reads. A first visit waits for its own result, with a delayed loading label for slow reads and no placeholder cards. Masonry measures its initial lanes before painting. Every empty category has its own icon, title and collection hint in English, Simplified Chinese and Taiwan Traditional Chinese. Request generations reject superseded reads and cursor pages during fast tab or filter changes.

## Copies, capacity and recovery

The default archive is `<userData>/library`; choosing a parent directory creates its dedicated `pith-library` child. A private ownership marker prevents adopting an unrelated nonempty directory. Original files remain untouched. Saved objects use SHA-256 names, exact byte copies, fsynced temporary files and atomic publication. Identical content shares one retained object across sessions, filenames and projects. Inline images are decoded for validation while their original bytes remain intact. Local file snapshots hold a descriptor and reject observed changes during copying.

The default quota is 2 GiB of archived content, including JSON web source records. The SQLite provenance index is separate under userData. Files are streamed in bounded chunks; an oversized file keeps its metadata and an explicit capacity status. Full archives preserve existing copies and continue recording sources. Lowering the quota below current usage also preserves copies; removing records releases an object only after its final reference disappears. There is no silent eviction and no fallback to opening an original when its retained copy is unavailable.

Every Web record uses a formatted UTF-8 JSON document with a versioned schema, title, URL/query when available, returned excerpt, capture time, source/tool and conversation/project provenance. Search/fetch text is bounded to 16,384 characters per source. References, downloads and query-only records use the same document with an empty excerpt; they never invent returned content or an offline website. Serialization selects collected fields explicitly and does not retain raw arguments, result objects, credentials or request headers. Networking is not replayed by the library. A reference-only snapshot can acquire the actual returned excerpt when live evidence arrives later; parameter-only replay cannot erase that evidence. Failed or capacity-limited enrichment retains the preceding physical copy and indexed evidence until retry saves the replacement. Later conversation-title updates enrich the index independently.

On first startup with a new web schema, retained index fields rebuild every visible Web record, including references previously stored only as metadata. This requires neither the original session nor a plain-text compatibility reader. Deletion tombstones survive and only unreferenced managed objects are released. Rebuilding existing records also works while automatic collection is paused; capacity failures retain indexed evidence and retry through recollection. Web snapshots always retain a `.json` object suffix, even when an attachment with identical bytes already uses another suffix, so preview routing cannot mistake them for ordinary text. Selecting a Web row opens the adjacent file pane on its JSON preview; Save As exports the complete document with a `.json` filename. The Library does not implement or customize the JSON tree renderer.

Archive migration verifies every object's size and digest before switching the durable physical-location pointer. A journal distinguishes incomplete target copies from an already committed move and permits targeted cleanup on restart. Cleanup touches only objects under a matching ownership marker. An unavailable existing archive is reported unavailable; startup does not recreate it empty and discard its object references. One worker and a database lock serialize archive writers. Quit stops collection and bounds worker disposal; persisted history supplies retry evidence after interruption.

## Verification

Run `npm run typecheck && npm run build`, then `npm test -- --no-prepare --suite library --suite library-ui --suite file-browser --suite preview-routing --strict-skips`. The integration suite covers actual SDK subscriptions and nested results, attachment/delivery-only files, exact bytes, dimension backfill, obsolete-record cleanup, deduplication, projects, JSON source/provenance fidelity, bounded Unicode excerpts, query-only sources, index-only format rebuild, quota/retry, deletion and category tombstones, filtered pagination, migration and restart. The Electron suite uses production preload/IPC/worker paths for spaced transparent photo walls, faster information and native double-click enlargement, stable delayed/broken image loading, shared three-line file/Web lists beside full text/Markdown/PDF/table/HTML/JSON previews, source-first Markdown and wrapping, JSON web export, source-website opening, resize, bounded file/Web pagination, keyboard and confirmation focus, filters, Save As, localization, settings, migration and confirmed category clearing. Shared file-pane changes also run file-browser, PDF/table and Markdown checks. Set `PI_LIBRARY_SCREENSHOT_DIR` to retain the UI gallery. No provider calls or real browsing accounts are required.
