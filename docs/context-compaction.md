# Manual context compaction

The titlebar and command palette share one request handler. Idle sessions compact immediately. During an agent run, a manual request waits until the current assistant response and its entire tool batch have finished and their results are persisted. The SDK's next request uses the summary; compaction adds no user message or new turn. A final response without tools is also a valid boundary.

`main/pi/manual-compaction.ts` owns one transient request per session and awaits the core `turn_end` listener. Repeated clicks share the pending operation. Navigation keeps it with the original session. Stop and queue recall with Stop cancel the request; disposal also settles the caller. Failed or truncated responses retain SDK recovery priority, with an idle fallback when the run has no successful boundary.

Admission and execution both check the selected model's `keepRecentTokens`. A session that is too small is refused without a summary row; admission rejection also emits no queue acknowledgement. A Plan branch-work reservation covers preparation through completion and prevents mode changes from racing the summary. Image replay, child sessions and scheduled sessions retain their existing interactive restrictions.

The pinned SDK's ordinary `compact()` aborts the current run. `scripts/prepare-pi-sdk.mjs` adds a version-checked `compactAtBoundary()` entry that shares the same manual summary implementation, hooks, persistence, events and cancellation while omitting that initial abort. Only the session-owned controller calls it, either while idle or from the awaited completed-turn boundary. Automatic threshold and overflow compaction keep their SDK paths.

`compaction_queue_update` publishes the transient pending action, with an independent revision and no `eventSequence` or persisted conversation entry. Snapshots include the same state; the renderer merges revisions across snapshot races and session navigation. Above the composer, the existing message queue displays a dedicated compaction icon, title and boundary hint. Message recall/promotion operates only on message payloads. The action notice clears when execution begins, admission is rechecked and refused, or the request is cancelled. `compaction_start` and `compaction_end` remain the execution and outcome signals; SDK failures use the existing transcript error presentation.

During execution, `SummaryRow` uses the ordinary tool disclosure component and the shared process-row width and spacing. A live assistant group renders it after the current output and before its spinner; before the first assistant response, the same row sits above the standalone spinner. Failed summaries retain their expandable error output, and completed summaries remain at their persisted transcript position.

An open compaction row has two regions. The fixed process header shows SDK preparation, summary generation and application stages, the actual summarized/retained message counts, trigger reason, elapsed time and recorded model requests. The final-summary region owns the existing bounded scrollport and file links. Context sizes are explicitly estimated; provider input/output billing belongs to the summary requests and is displayed separately. Legacy summaries show an unavailable-process note instead of reconstructed timing or requests. Disclosure choices follow the process identity when the live row becomes a persisted summary row.

`main/pi/compaction-process.ts` observes the SDK's public `session_before_compact` preparation hook and the existing trajectory recorder's request metadata. It does not consume stream chunks, replace summaries or alter admission. Request attempts are bounded, and `compaction_process_update` has a separate revision without `eventSequence`; snapshots and background-session caches merge the same revision. Cancellation and failures settle the current process. Successful process receipts are private branch entries linked to the actual compaction entry, outside model context and visible messages; reopening, peeking and copied branches retain their recorded statistics. Old branches do not borrow another summary's data.

Run the `context-compaction`, `plan-mode`, `session-lifecycle`, `bash-task-ui`, `transcript-rhythm` and `window-chrome` suites after typecheck and build. Fixtures use the real SDK and an offline provider; they do not establish real-provider summary quality.
