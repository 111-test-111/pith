# Session sidebar

The session sidebar composes pi-app's beUI primitives and theme tokens. Its three views are projects, custom groups and a timeline. Pinned sessions remain a separate section in each view. Projectless chats never expose their internal working directory.

## Ownership

`Workspace` owns session discovery, navigation and SDK mutations. `SessionsSidebar` owns the list's filters, paging, menus and editors. `lib/session-sidebar.ts` validates and persists presentation preferences under the existing `pi-app:session-sidebar:v1` key, preserving earlier pins and manual ordering.

Preferences include view, sorting, group membership, section/project order, collapsed sections, unread marks and archived paths. They never rewrite an SDK session's cwd or history. Custom groups can contain sessions from several projects; membership changes require an explicit group action. Dragging only reorders rows within their existing section and project. Automatic date sorting and timeline rows cannot be manually dragged.

Creation times come from session headers in the main-owned listing index. Refreshes use the existing fingerprint cache and live session derivation; changing the view or a filter does not rescan session files.

## Automatic titles

Settings → General → Automatically name conversations defaults to on. Settings → Providers → Default model includes a conversation naming model; leaving it unset uses the conversation's current model without changing its selection. These app-local preferences do not change the Pi CLI's default model.

`main/pi/session-naming.ts` owns one background naming job per regular conversation, using a no-tools completion. It starts as soon as the SDK persists the first user message, outside the awaited message event stack. Naming runs independently of the main response and updates the title while tools or replies are still running. Its bounded input comes from the full selected branch's first user message, optionally including an already committed successful assistant reply from the first turn, omitting thinking, tools, image bytes and inlined attachment bodies. Textless input can start from the first successful assistant text, including a reply that also calls tools; `agent_settled` remains a fallback for a temporarily unavailable checkout. The title follows the user's language, aims for 4–6 English words or 6–14 Chinese characters, and is limited to 40 graphemes and eight words. Multiline, empty, overlong and failed responses are unusable and retried.

The existing first-user-message fallback (80 characters) stays visible while naming runs and after failure. Each request has a 20-second hard deadline; at most three attempts use 1-second and 3-second retry delays, with SDK retries disabled. Failures emit no chat error or notification. Private session entries persist the attempt budget before dispatch; restart resumes only a pending job and never bulk-renames history. Enabling naming or changing its model during a live conversation can start it immediately. Exhaustion survives later turns and restart. Actual returned usage is persisted separately under `session-naming`, attributed to the naming model without entering the conversation context.

Every explicit `session_info` entry, including an empty manual clear or a CLI/extension title, takes priority. Settings changes, Stop and disposal cancel pending requests; switching the active conversation retains the original owner. Stop pauses naming until another user message is accepted. Each job freezes its source entries; later assistant replies do not invalidate it or change its input on restart. Results recheck those entries, the selected Rewind marker and checkout/recovery exclusion before appending, and metadata writes stay outside the SDK's awaited persistence/commit checks. Children and newly created scheduled-run sessions never own a naming service. Successful names use the SDK's `setSessionName` and sequence-free `session_info_changed` metadata, so the sidebar refreshes background titles through its existing listener.

`session-naming` covers timing, model inheritance/overrides, persistence, usage, silent retries/fallback, manual titles, switches, cancellation, selected-branch changes and restart. `settings-tabs` covers the checkbox and naming model picker.

## Appearance

The translucent sidebar preference defaults to on and persists separately in `lib/sidebar-glass.ts`. On macOS, `window-chrome.ts` provides an active native vibrancy material behind the window, with a transparent WebContents background from `main/index.ts`. Both the page body and Workspace's `ChatApp` shell must leave that material visible: an opaque ancestor hides it even if the sidebar panel itself is translucent. The panel adds a light veil and accent wash; the title row and conversation retain their own opaque surfaces. Disabling glass restores the sidebar's opaque surface and removes the wash. Other platforms retain the opaque page background, and the narrow-window sheet stays opaque.

## Archive and delete

Archive is a reversible presentation operation. Archived sessions leave the ordinary views and remain in the dedicated archive view, including after a restart. Opening or continuing an archived session does not implicitly restore it. Unarchive returns it to its original project and custom group, with its pin and ordering preserved. Archive remains available while a session is running and does not stop its work.

Delete retains the existing confirmation and main-process Trash operation. Removing a custom group only removes its presentation grouping. Neither operation is substituted for archive. Indexed history search continues to search archived sessions.

## Interaction and verification

The list supports all/running/unread filters, updated/created/manual ordering, persistent collapse state, expand/collapse all and per-section paging. The free-text title/project filter was removed: indexed history search is the only text search. The session-options popover contains group/project/timeline selection, ordering, filtering, archive navigation, expand/collapse all and group creation when applicable. The resting header keeps search, scheduled tasks and the options trigger; an archived list adds a return button there. Session rows use the interface line height plus 8px, preserving compact density as the configured font size changes. A completed `agent_settled` marks an unseen conversation unread, including when another conversation or page is open, the rail covers the transcript in fullscreen, or the window is unfocused/hidden. Intermediate `agent_end`, continuing runs, user-stopped runs and subagent turns do not create unread marks. The theme-accent dot persists through reloads until the conversation is viewed in a focused window; successful navigation, returning from a covering page and regaining window focus acknowledge it. A single context-menu target resolver serves the list; row action menus use the same action definitions. Rename failures retain the previous title and report an error.

Session rows show one line with no leading glyph or project/date subtitle; running indicators sit to the right of the title. Titles remain stationary and keep their single-line right-edge fade across the available row width. Floating row actions overlay the title without reserving an empty column or shifting it on hover. The entire session row triggers one beUI tooltip after a short delay. Its title wraps for up to six lines, followed by message count, date and the visible project path. Projectless workspace paths remain private. Group paths also use beUI tooltips; native `title` bubbles are absent. Tooltips are portalled outside the list's clipped scrollport and suspended during editing, dragging or an open row menu without replacing the row.

`session-sidebar` covers preference migration, sorting, grouping, archive restoration and membership constraints. `sidebar-list` exercises the built renderer's views, archive/restore, group actions, filtering, persistence, keyboard navigation and scrolling. Adjacent session-list, session-search and new-session-project suites protect index and navigation boundaries.

`sidebar-glass` covers preference persistence, theme/accent changes and the narrow-window sheet. `window-chrome` captures the built workspace's composited alpha through the production native chrome settings, including the page and shell ancestors, and checks the Appearance toggle along with opaque title/conversation surfaces. Run these after `npm run typecheck && npm run build` with `npm test -- --no-prepare --suite sidebar-glass --suite window-chrome --strict-skips`.
