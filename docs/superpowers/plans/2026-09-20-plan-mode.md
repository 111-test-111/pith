# Plan Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 pi-app 增加受 DSH 约束的 Plan Mode，交付会话内可版本化计划，并由用户显式批准后在同一会话执行。

**Architecture:** 独立工作模式覆盖实际权限，但保留用户原沙箱选择。应用拥有的工具适配器、分支投影和批准控制器负责安全边界；Renderer 仅消费 DTO、展示计划与发起显式动作。保留现有 SDK、DSH、子代理和 Rewind 的所有权，不另建执行引擎。

**Tech Stack:** Electron main/preload、Pi SDK 0.85.1、TypeScript、React、beUI、TypeBox、esbuild + Node assert + 现有 Electron/CDP 检查脚本。

**Spec:** [已批准设计](../specs/2026-09-20-plan-mode-design.md)，用户已确认；本计划不重新开放已决设计问题。

## Global Constraints

- 运行时限制而非仅提示；复用现有 DSH；会话内计划卡片；批准后在同一会话执行；计划文件仅按需导出。
- Plan 下，应用拥有的文件修改工具不可用；模型 shell 固定使用 DSH `read-only`，不能申请一次性提权。
- 现有 DSH 不隔离网络，不能阻止 shell 调用远程写 API。因此第一版不承诺远程服务或数据库的强制只读。
- 扩展属于受信任宿主代码。工具过滤不等于隔离恶意扩展的 Node.js 工厂、生命周期 hook 或磁盘访问。
- 第一版仅在会话及其子代理、后台任务和待交付结果全部满足准入条件时切换模式；不得清队列或自动停任务以使检查通过。
- `SessionMode` 不加入 `SandboxMode` 枚举。进入 Plan 不改用户原权限或全局默认；批准不自动扩大权限。
- 模型只提供完整 Markdown，不提供计划 ID、版本、路径或批准状态。正文设 128 KiB UTF-8 上限，超限不能截断后保存。
- 新 UI 全部使用 beUI、主题 token 和双语 i18n。主进程返回错误代码及参数，Renderer 负责用户文案。
- 不增加依赖、不 fork SDK、不修改 node_modules、不改 vendored beUI；实现时使用隔离工作区，遵循 using-git-worktrees 技能。
- 所有新 API 从 shared/types 导出；Renderer 不导入 Electron、Pi SDK 或 main 模块。
- `agent_settled` 才是 SDK run 结束依据，但 app 后台工作和队列仍须独立检查。
- 每项按红→绿执行并提交；提交前检查只包含本项文件。最终执行 `npm run typecheck && npm run build` 及本计划列出的回归。

## 实施前已核实的 SDK 接点

1. `agent.beforeToolCall` 的公开 context 包含 `assistantMessage`、`toolCall`、`args`、`context.tools`。先检查整批，再串接已有 hook，最后复核真实参数；不能覆盖 Rewind/extension 的 hook。
2. `agent.shouldStopAfterTurn` 是公开 hook，在 `turn_end` 后、消费 steering/follow-up 前调用。`terminate: true` 本身仍可能消费这些队列。
3. 动态工具注册和 reload 最终调用公开 `session.setActiveToolsByName`。SDK 没有 `tools_changed` 事件；包装公开 setter 是本应用适配器，必须有升级回归。
4. `createReadOnlyTools(cwd)` 公开返回四个完整 AgentTool：read/grep/find/ls。替换必须包含 schema、description 和 prepareArguments，不能只换 execute。直接替换不会更新 SDK 的 ToolInfo/prompt metadata，应用需维护自己的实际工具视图。
5. `before_agent_start` 不覆盖 idle custom-message wake 或 agent retry；`context` 覆盖这些普通 agent 请求，但不覆盖默认压缩。默认压缩和分支摘要使用公开 `agent.streamFunction`。
6. SDK 的 session `message_end` listener 先运行，随后才 append。持久化投影和批准开场关联使用**后注册、awaited 的 `agent.subscribe`**，不要直接照搬 Todo 的同步 session listener。
7. `SessionManager._appendEntry` 先修改内存再写磁盘。写失败后不能仅 fold 内存并宣称成功；持久化错误必须关闭工作准入。应用已有 `materializeSession` 可让空会话先落盘。

实现时先读 [AGENTS.md](../../../AGENTS.md)、已批准规格，以及所修改模块对应文档。SDK 文档位于安装包 docs；用已核实公开 API，测试中不要假装存在专用 policy/registry-change hook。

```ts
// main/pi/plan-storage.ts
export class PlanStorage {
  failed = false
  constructor(private manager: SessionManager) {}
  append(customType: string, data: unknown): string {
    if (this.failed) throw new Error('plan-storage-locked')
    try {
      const id = this.manager.appendCustomEntry(customType, data)
      this.sync()
      return id
    } catch (error) { this.failed = true; throw error }
  }
  sync(): void {
    if (this.failed) throw new Error('plan-storage-locked')
    const path = this.manager.getSessionFile()
    if (!path) { this.failed = true; throw new Error('plan-session-not-persisted') }
    try {
      const fd = openSync(path, 'r+')
      try { fsyncSync(fd) } finally { closeSync(fd) }
    } catch (error) { this.failed = true; throw error }
  }
}
```

初始化模式前由 manager 现有 materializeSession 落盘。对 append 抛错后已进入内存的条目，安全锁优先于 fold。提交结果的磁盘同步失败也锁住，不发布可批准状态；记录不可写时不要继续追加“成功回滚”。
